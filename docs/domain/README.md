# 领域规格

本目录是本项目**领域概念的规格真源**，供本仓库及其他实现仓库直接引用。

领域文档描述的是「这个概念是什么、有哪些不变量、允许哪些状态流转」，**不描述如何实现**。

## 与 `AGENTS.md` 的关系

- 根 [`AGENTS.md`](../../AGENTS.md) 是**协作规则**的真源；本目录是**领域语义**的真源。两者管辖范围不重叠。
- `AGENTS.md`「项目高风险清单」的条目名称沿用业务主线措辞，**不构成设计约束**。当条目措辞与本目录的文档冲突时，**以本目录为准**，并同步修订清单。
- 反过来，本目录不得放宽 `AGENTS.md` 的协作规则、风险卡点与验收标准。

## 文档写法约定

每份领域文档必须包含以下部分，缺一不可：

| 部分 | 要求 |
|---|---|
| 概念定义 | 每个概念一段定义，写清「它代表什么」，不写字段列表 |
| 不变量 | 编号列出（`I<n>`），每条是可证伪的断言，并标注**目标固化层级** |
| 状态机 | **状态取值表**（每个状态显式标注是否终态）+ **流转矩阵**（逐一列出全部有序状态对，每格标 允许 / 禁止）|
| 引用纪律 | 本概念被其他上下文引用时，允许持有什么、禁止持有什么 |
| 边界与非目标 | 显式写出本文档**不**定义什么，以及不定义的理由 |
| 待澄清问题清单 | 已知的认知盲区，作为下一轮的输入 |

### 状态机必须写成矩阵，不写成散文排除句

状态机小节**禁止**用「X → Y 以外的任何逆向流转都不允许」这类散文排除句列举非法流转。这类句子天然产生两种读法（被排除项究竟是例外还是被禁止），而领域规格的唯一职责就是消除读法分歧。

必须改用 n×n 流转矩阵逐格标注，每个有序状态对都有明确取值，**不存在「未定义」的第三种取值**；并在状态取值表中逐个标注是否终态——每个状态机至少有一个终态，且每个非终态必须存在通往某个终态的路径。

该约定的**结构部分可以机检**（矩阵是否覆盖全部有序状态对、每个状态是否标注终态）。当前**尚未固化**，见「约定的固化归属」。

### 不变量必须标注目标固化层级

按 `AGENTS.md`「约束落地优先级」，散文规则是最后手段。每条不变量必须标注它**最终应该落在哪一层**：

- `类型`：可由类型或接口签名使其无法表达违反写法。
- `检查`：无法由类型固化，但可由测试、契约测试或 CI 断言。
- `文档`：确实只能靠人工遵守，必须写明为何前两层做不到。

实现仓库落地该领域时，标注为 `类型` 与 `检查` 的不变量**必须**下沉到对应层级；仍留在文档层的，属已知欠账。

### 不写技术栈

领域文档中不得出现语言、框架、存储、表结构、字段类型、序列化格式、目录结构。出现即为缺陷。

### 断言中的每一项都必须可取值

标注为 `检查` 层的不变量，其断言中出现的**每一个项**都必须在同一份文档内有可判定定义。若某项在已定义的某个子类下无法取值，**必须显式写出该子类如何处理**，不得笼统写成「对所有 X 成立」。

标注了固化层级不等于该层级可实现。一条不可判定的不变量比没有这条不变量更糟：它看起来提供了保护，实现方却只能在两种落法之间自行选择，而选择不会被记录下来。

## 约定的固化归属

本节逐条说明上述约定当前**实际**落在哪一层。按 `AGENTS.md`「约束落地优先级」，能前置固化而未固化的，是**已知欠账**，必须如实标注。

**「已固化」是一条可核对的事实陈述**：被引用的检查必须是仓库内受版本控制、且由 CI 或钩子实际运行的产物。一次性脚本不算。

| 约定 | 可机检？ | 当前固化状态 | 说明 |
|---|---|---|---|
| 状态机必须含状态取值表与流转矩阵，矩阵覆盖全部有序状态对，每格取值只能是「允许」「禁止」或对角线 | 是 | **未固化** | 纯结构断言，成本极低。承接入库的 issue 见下 |
| 每个状态机至少有一个状态标注为终态 | 是 | **未固化** | 同上 |
| 每个非终态存在通往某个终态的路径 | 是 | **未固化** | 需在矩阵上做可达性计算，未实现 |
| 每份领域文档含全部必备部分（含「引用纪律」） | 是 | **未固化** | 须对本目录下**全部**文档生效，不得硬编码单个文件路径 |
| 每条不变量的固化层级列取值只能是 `类型` / `检查` / `文档` | 是 | **未固化** | |
| 不变量编号连续，且正文引用的编号在表中存在 | 是 | **未固化** | |
| 相对链接、页内锚点、双方括号记忆引用可解析 | 是 | **未固化** | |
| 领域文档正文无技术栈词汇 | 是 | **未固化** | 豁免必须逐行登记，不得按否定词整行跳过 |
| 分项承接表以来源侧（`AGENTS.md` 高风险清单）为遍历基准 | 是 | **未固化** | 来源侧分项须解析得到，不得硬编码 |
| 「检查」层不变量的断言中每一项是否真的可取值 | **否** | 文档层 | 输入是语义而非结构，只能靠人工判断 |
| 状态机各状态的语义是否正确 | **否** | 文档层 | 同上 |

**当前没有任何针对本目录的自动化检查在 CI 中运行。** 上表中标「未固化」的九条，都只在本轮以一次性取证脚本实跑过，对后续提交无回归防护。入库由独立 issue 承接——在它落地前，这些约定的实际效力等同于人工评审。

## 变更规则

本目录的任何语义变更**默认命中高风险**（`AGENTS.md` 高风险判定标准 2、7：被其他仓库依赖的契约、跨模块影响），必须走完整的人工确认与评估器审查流程。

文档已被实现引用后的语义变更，**同时**按「破坏性变更」处理。

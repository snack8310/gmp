# 沉淀「已固化是可核对的事实陈述」，并上调计数规则强度

关联：issue #15（来源：issue #10 的另一条路径 PR #14，已关闭）

## 背景

`AGENTS.md`「约束落地优先级」把自动化检查排在规则文档之前，`shell-script-portability.md` 也写过「未固化的部分仍是文档约定，不得声称为已固化」。但那份文件的标题、原因段与落地层级表全部是 shell 语境，实践中被读成 shell 专属规则。

同类失效已在本仓库出现两次，都不在 shell 语境：

1. PR #11 的变更证据中，「设计词漂移检查」一行被如实撤回——该检查所依据的规则对 `docs/domain/` 下一份文档也不成立，而检查当时确实跑绿过。
2. 已关闭的 PR #14 中，文档写下「以下约定已固化为自动化检查」，而承载断言的脚本在会话临时目录、合并后即不存在，CI 中无对应检查；同一 commit 的变更证据在别处又写着「未入库」。

两者的共同性质是：**看起来是修复，实际是把欠账挪到看不见的地方。**

## 关键实现

- 新增 `mechanization-claims.md`，把该规则从 shell 语境中提出来。规则涵盖：固化声明的事实性要求、固化归属表的强制形态、穷举式表述的比对义务、评估器要求下沉时的正确回应、规则被推翻后历史绿灯必须撤回、结构性检查脚本必须配空断言变异且发现驱动的循环必须配数量下限断言。
- 该文件按自身规则 2 标注「本文件描述的规则目前全部未固化」，并给出逐条固化归属表。表以**规则标识为键**，判据写死为「键按出现顺序去重后与规则清单编号序列完全相等」而非行数相等；规则 4 拆两行共用同一键；可机检项附承接编号 #12。
- 修订 `source-enumeration-fidelity.md`：计数规则由「尽量不写、确需时以实测为准」上调为「禁止在送审载体中书写由工具产生的计数」。逐字保留原条文与上调理由，并划清豁免边界——豁免的是「计数只在执行时产生、不被转写进载体」，**不是「它出自工具」**：把工具输出的计数原样粘进载体同样禁止。

## 关键文件

- `docs/history/memory/mechanization-claims.md`：新增。
- `docs/history/memory/source-enumeration-fidelity.md`：修订「送审摘要」一条，其余未动。

## 风险与未覆盖项

- **真风险（放行后续跟进）**：`mechanization-claims.md` 中判为可机检的规则——规则 1（固化声明引用的检查须真实存在且被 CI 调用）、规则 2（禁止整体式声明；归属表键集合与规则清单同序同基数）、规则 4 的编号部分（未固化声明须附 issue 编号）、规则 6（新立结构性规则须对存量同型产物全量复核）、规则 7（空断言变异与循环下限断言）——全部未固化，由 #12 承接。在它落地前，这些规则的实际效力等同于人工评审，而本仓库的历史恰好证明人工在这一类上会连续失手：本次记忆文件的初稿自己就漏掉了规则 2。
- **真风险（仅观察）**：`mechanization-claims.md` 与 `shell-script-portability.md`「落地层级」一节在规则上部分重叠。本次选择保留重叠并交叉引用，未动后者——后者是一份已生效的记忆，改它需要单独评估。重叠意味着两处可能各自演化。
- **本次不覆盖项**：不回改历史变更证据中已有的计数（`2026-08-30-shell-ci-gate.md` 的「100 条断言」等）。历史记录是冻结快照，回改本身是伪造。
- **未定调项**：上调后的「禁止计数」与「第 N 条」这类序数引用的判别标准，只写在 `source-enumeration-fidelity.md` 的正文里，没有机器判据。#12 落地时需要给出可判定的边界，否则门禁正则会误伤序数引用。
- **存量违规登记（已在 #12 留言登记，见该 issue 的 comment）**：按新增的规则 6，本次对仓库内同型存量产物跑了一遍新规则。已发现的不合规项如下——**这不是穷举**，#12 落地时应对 `docs/history/memory/**` 与 `test/**` 全量执行：
  - `docs/history/memory/shell-script-portability.md` 的固化归属表违反规则 2：其规则清单的最后一条（「上述前三条的验证用例应包含：zsh 解释器、末行无换行符、分支名含通配符字符」）在表中零行，既未标已固化也未标未固化；而表行数恰好等于规则数，漏项被这个假信号掩盖，与本文件初稿的失效形态逐字同构。**本次不改它**——它是一份已生效的记忆，且 issue #15 非目标限定本轮只落记忆文件；在此如实登记。
  - `test/docs/consistency_check.py` 违反规则 7：`check_struck_facts_are_not_cited`、`check_classification_grounds_hold`、`check_change_records_match_products` 均为发现驱动且无数量下限断言，`docs/domain/README.md` 的「文档清单」标题一改即静默清零仍打印通过。改它落在 issue #15 非目标内（本次不新增或修改任何自动化检查）。

## 评估器审查

首轮结论 `FAIL`。阻断问题与修复：

| # | 阻断问题 | 修复 |
|---|---|---|
| 1 | 固化归属表漏掉规则 2 自己。表的行数恰好等于规则数，看上去一一对应，实际是规则 4 占两行、规则 2 零行——而规则 2（禁止整体式声明）恰恰可机检，漏掉后既未进 #12 也未标文档层，成为不在任何一栏里的欠账 | 表改为以**规则标识为键**、与规则清单同序同基数，拆行共用同一键；规则 2 正文补入表形态的硬要求：键的去重序列须与规则编号序列相等、拆行共用同一键且相邻、「行数恰好等于规则数」不构成完整性证据、无编号清单须先编号、判「是」须附固化位置或编号且判「否」须写明理由 |
| 2 | 交给 #12 的规格「解析固化归属表 → 校验引用的检查存在」是发现驱动、无下限断言：表不存在或标题改写时零行通过——写死了本文件规则 6 刚禁止的空断言形态 | 规格改写为「表缺失、标题被改写或键集合为空一律判失败」，并在正文写明该下限断言不是可选项 |

两条同源：本文件初稿自己踩了它要立的规则。该反例已写入规则 2 与「原因」段。

复审结论 `FAIL`，一条阻断：新立的表形态要求未对仓库内**存量**同型产物复核，`shell-script-portability.md` 的归属表当场违反；且变更证据写了「第一条真实反例」这一当场可证伪的穷举断言。修复：新增规则 6（新立结构性规则须对存量同型产物全量复核并登记不合规者），存量违规如实登记且改为非穷举表述。**该阻断的根因是本文件只对自己新写的产物负责**——规则 6 即由此而来。

# gmp-core 第四轮：scenarios 跨层回归用例，与一个能跑的 demo

关联：issue #36

## 背景

三层已落地（#23、#32、#34），但**仓库里一个 `main` 包都没有**——`go build` 编译通过却不产出任何二进制，唯一的运行方式是 `go test ./...`。

同时有两个缺口：

1. **`gmp-core/scenarios/` 不存在**。`system-boundaries.md` 的 B7 早已指定它是跨子项目场景测试的落点，依赖分层表里也早有这一层。已建成的功能只被各自包内的用例驱动，没有任何一处把三层串起来按业务场景走一遍。
2. **根 `AGENTS.md`「业务回归用例 · 当前状态：尚未建立」一字未改**，而近三轮的变更证据反复写「部分解除」。**规则真源与变更证据已经不一致**——这正是本仓库反复吃亏的形态，而这次是主 Agent 自己犯的。本轮纠正。

## 关键实现

**跨层回归用例（`gmp-core/scenarios/`）**

- 承接**跨层**的业务场景，只涉及单层的仍留在各自包内——落点判据照 B7，没有把单层能测的东西搬个地方充数。
- 场景 ③ 跨 `audience` 与 `campaign`：从人群判定到抢位裁决到决策表路由，新客 / 老客 / 其余各自落点正确，输家留痕可查。
- 场景 ④ 跨全部三层：放量从前 5 份到 20 份到 100 份，**已进来的人一个都不掉**，且未纳入者的落败原因必须是放量本身（否则比较会被别的原因污染）。
- 场景 ② 跨 `audience` 与 `experimentation`：四臂恰好划分基础人群；**对照组在系统里存在**，且能与「压根不在人群里的人」分开。
- 演练贯穿三层：以演练模式跑完整条链后染色记录数不变，真实模式下不为零（否则该断言空转）。

**装配根是共享的，不是各写一套**

`Stack` 是普通代码而非测试辅助，demo 与回归用例装配的是同一套东西。两套装配一旦漂移，演示的就不是被测的。

**能看的 demo（`gmp-core/cmd/gmp-demo/`）**

装配三层，把上述场景走一遍并打印结果。不读配置、不起服务、不落盘。它是演示与手动核对用的，**不是回归**——回归由 `scenarios` 承担，这一点写在它的包注释里。

**写 demo 时抓到一处自己的误导输出**：演练那节原本复用前面已经跑过的样本，染色记录早已非零，于是「真实跑一遍后」的数字看起来跟演练后一样——**读起来像是真实模式也不染色**。改为用一份干净样本重跑该节，现在显示「演练前 0、演练后 0、真实跑一遍后非零」。

**门禁**

- 分层表增至四层。
- **新增一条表本身的完整性断言**：`gmp-core` 下每个存在的层目录都必须在表内。此前新增一层却忘了登记，不会有任何东西失败——表是分层唯一被写下来的地方，漏登记的层等于完全不受检查。`cmd` 与 `internal` 显式排除并写明理由，而不是默默漏掉。
- **CI 新增一步真的跑 demo**。编译不等于能跑：它可能编译通过却在空 map 或未处理的错误上炸掉。

**纠正漂移**

根 `AGENTS.md`「业务回归用例」的状态改为**逐场景如实清单**，不停在「尚未建立」，也不含糊地写「已建立」。未建立的部分仍适用原规则。

## 风险与未覆盖项

**真风险（仅观察）**：

1. **demo 的输出不做断言**。CI 只保证它能跑通、退出码为 0；输出写错了不会红。这是有意的——快照断言会把可读性改动变成红灯，而 demo 的定位是给人看。**它不是回归，这一点写在包注释里，以免日后被当成保障。**
2. **`cmd` 完全不受分层约束**。装配根按定义要看见所有层，但这意味着有人把逻辑写进 `cmd` 就绕开了分层。表完整性断言把它**显式排除**而非默默漏掉，理由写在代码里，但约束本身确实不存在。

**本次不覆盖项**：

- **场景 ① 与 ⑤ 未建立**，它们需要事件串与执行侧，两者都没建。demo 结尾会把这一条打印出来，不让运行结果看起来比实际完整。
- 场景 ② 的触达与指标部分、场景 ④ 的执行部分——批量执行路径未建，表达不了的部分如实缺席，**没有硬塞进当场决定那条路径**。
- 真实存储、真实渠道、HTTP 服务、部署形态、配置文件——`docs/domain` 的禁止侧。
- 不新增任何领域语义；`docs/domain/` 一字未动。
- **高风险清单的卡点密度复审未做**。触发条件是「抽象稳定 + 开始做增量功能 + 业务回归用例已建立」三条同时成立。本轮第三条**部分**成立，前两条均不成立——执行侧未建，仍在建核心抽象。`2026-09-01-tech-stack-decided.md` 曾记「该免除条件将由 #23 自己解除」，**本轮如实登记为仍未解除**，不顺手复审。

**需要后续动作的事项**：

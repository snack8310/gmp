# 把文档门禁本身变成可被证伪的（#12 第一轮）

关联：issue #12

## 背景

`test/docs/consistency_check.py` 自建成起**零测试**，而它的每一条检查都是发现驱动的——改个目录名或小节标题，循环体一次都不执行，退出码照样是 0。

issue #12 的硬约束 1 正是「脚本自身必须配空断言变异测试」。这是所有新增检查的前置：**没有它，新加的检查只是更多不知道自己有没有在工作的绿灯。**

**动手前先核实 #12 还剩什么**，结果是一部分条目已失效：正文中引用的旧版 `docs/domain/README.md` 约定——状态机流转矩阵、不变量固化层级列、引用纪律——在 README 重写后都已不存在。本轮只承接现行约定仍支持的部分，并如实记录哪些失效。

## 关键实现

**变异测试框架**

新增 `test/docs/consistency_check_test.py`：每个用例把真实文档树复制一份、只破坏一处、要求门禁必须报出**对应的那条检查**。同时要求「什么都不破坏时必须干净」——否则这些用例只能证明门禁对一切都报错。

为此把检查脚本改成**可以被指向别的树**：一个没法瞄准别处的门禁，就没法证明它的牙齿。

**给既有检查补数量下限断言**

这是 #15 在本 issue 下登记的存量违规之一：既有三条检查是发现驱动且无下限，`README` 的「文档清单」标题一改，其中两条即静默清零、仍打印通过。

**修 #15 登记的另一处存量违规**

`shell-script-portability.md` 的固化归属表漏掉规则清单的最后一条，而**表行数恰好等于规则数**，漏项被这个假信号掩盖。该文件的规则清单此前没有编号，按 `mechanization-claims` 规则 2「被检查文档若没有编号规则清单，必须先编号」，一并编号后补入漏行。

**新增经实证有价值的检查**

- **跨文档的事实引用**（来自 #28）：既有 check 1 只在同一份文件内生效，而设计文档引用的事实全部来自别处——该空洞本轮补上，含「限定词写法」与「不带限定词时归属哪份文档」的判定。
- **承接表必须覆盖它声明的遍历基准**（来自 #28）：那一轮实测漏了四条，而人工核对时它们看上去是齐的。
- **设计文档必备章节齐全**（现行 README 约定）。
- **同一语义色只有一个取值 / 对比度可重算**（来自 #30）：后者曾抓到一处目视完全看不出的不达标取值。
- **相对链接解析**：此前每轮都靠手工核对。

**为可机检重排了 `design-system.md` 的色彩一节**

原来对比度表写「次级」而角色表写「次级文字」，机器对不上。现在收敛成**唯一一张色板表**，其余各处只引用角色名——这本身也正是「同一语义色不出现两个取值」要保证的性质。**取值一个未变**，由新增的对比度重算断言实测保证。

## 变异框架当场抓到两处我自己的缺陷

两处都不是实现错，是**断言与夹具的错**，而且都只有跑变异才看得见：

1. **下限断言被合并计数**。把 `docs/product/` 并进遍历基准后，下限成了两个基准的合计——**删掉整个 `docs/domain/` 也还有条目，检查照样通过**。改为按基准分别断言。
2. **夹具不完整**。夹具只复制了 `docs` 与 `AGENTS.md`，于是指向 `gmp-core/README.md` 的链接在夹具里解析不到，「什么都不破坏」这一条当场报红。夹具本身是被测对象的一部分。

## 实测推翻的一条：撤掉了一个已写完的检查

原计划包含「声称由 issue 承接的行必须同行给出编号」（#15 在本 issue 下明确留给它的部分）。写完在真实树上一跑，报出的**五处全是误伤**，且是同一类：

- 三处是在**陈述规则本身**（「承接行须给出 issue 编号」），
- 一处是「还需要开一个 issue」——尚未主张已有承接方，
- 一处是冻结的历史记录，且它自己写明了「该 issue 尚未创建」。

用模式匹配无法区分「这句话在应用规则」与「这句话在陈述规则」。继续加豁免正是 #12 正文自己担心的形态——「豁免机制怎么设计，才不会退化成『加一行豁免就绕过』」。

**据此撤掉该检查，并把这次实测当作对 #12 未讨论项 1 的回答**：这一类断言靠正则做不到可接受的精度，要么换判据，要么承认它留在文档层。

## 风险与未覆盖项

**真风险（仅观察）**：

- **夹具与真实树可能漂移**。变异用例跑在真实树的副本上，所以夹具需要覆盖被链接到的目录；今天列了一份清单，新增顶层目录时若忘了加进去，「什么都不破坏」那条会直接报红——**这个失效是响的**，不是静默的。

**本次不覆盖项（#12 仍未关闭）**：

1. **计数禁令的序数 / 计数边界**（#12 未讨论项 1）。本轮以同类实测给出了证据，但未给出判据，也未落地检查。
2. **固化归属表键序列的通用机检**。本轮只修了已知的一处违规；`mechanization-claims.md` 自身的归属表未被机检。
3. **条目级交叉引用解析**（#12 正文列出，本轮未做）。
4. **冻结历史记录是否受新门禁约束**（#12 未讨论项 2）。链接这一项已全量生效且通过，该问题在这一项上无争议；其余项仍未定调。
5. **送审载体（PR 正文、commit message）不在任何遍历基准内**——门禁只看仓库内的文件。

**需要后续动作的事项**：

- 人工裁定：撤掉「承接行须给编号」这条检查是否认可，还是应换一种判据再试。
- 人工裁定：上述五项未覆盖项中，哪些值得做第二轮，哪些应当明确判为不做。

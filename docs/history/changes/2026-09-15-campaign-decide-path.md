# gmp-core 第三轮：campaign 层的当场决定路径

关联：issue #34

## 背景

`experimentation`（#23）与 `audience`（#32）已落地。第三层是 `campaign`，只允许依赖 `audience`。

本轮不做整层，只切一条路径——**场景 ③：APP 拿一个 uid 来问，平台当场算该给他看什么**。`interaction-invariants.md` 的不变量 5、9、14 全部落在这条路径上，而它们此前只是断言：决策表条件重叠没人告诉运营、同活动两个投放项抢同一位会同时命中一个人、抢位输了不留痕就无从查起。

一次做完整层是 PR #14 的死法，本轮显式否决。

## 关键实现

**领域模型（`gmp-core/campaign/`）**

- **投放项只决策、不执行**。裁决产出的是一个值（注册过的动作 + 参数），路径上不存在任何对外调用。这不是洁癖：决策与执行分开，才能在不真发出去的前提下算出「这个人会收到什么」，而触达不可撤回。
- **优先级没有可用的零值**。忘了设的活动会排到最低、永远不赢，而这看起来跟「它确实没命中」一模一样。
- **平局显式报不可裁决，不臆造规则**。规格只说「优先级全局一个」，从未说过两个活动同分怎么办。挑一个等于把选择藏起来——输的那个看起来像是压根没命中。
- **同活动内两个投放项抢同一位子，构造期就拦住**。放行条件是二选一：决策表把它们排了序，或它们的人群**可证互斥**。
- **可证互斥是保守的、单向的**。唯一的证明是「同一次分流修订的不同份」——一个键在一次切法里只落一份。属性看起来不相交不算数：「看起来互斥」正是两个投放项同时够到一个人的成因。
- **决策表守三件事**：顺序（从上往下、第一个命中生效）、兜底（必须有，「不走」也是一种兜底）、**可证走不到的行直接拒绝**（某行要求的条件是前面某行的超集时，它一个人都走不到——数据恒为零会被读成「效果不好」，而不是「它从没跑过」）。
- **放量闸门作用于整个活动**，不是逐个投放项。挂到投放项上会让各实验臂放量不同步，实验结论当场失效且不报错。
- **放量表达成一份人群定义**。领域文档本来就说「放量 = 当前纳入这次分桶的哪几个桶」「第 N 份只是人群定义里的一个条件」——这样 `campaign` 不必反手去够 `experimentation`，分层自然成立。为此给 `audience` 新增了「落在第 N 份或更前」这一个条件。
- **动作是研发接入的能力清单**，每个动作自报参数。不设统一的「内容」模型：券种是外部券系统的标识，包成平台概念只会让券系统一改这边就疼。
- **留痕覆盖全部输家**，每条带落败原因。只记可从裁决本身推出的字段。

**依赖方向门禁（`gmp-core/internal/arch/`）**

分层表增到三层。**扩表时被自己的检查拦下了一次**：`campaign` 的测试装配代码 import 了 `experimentation`——测试要构造三层才能接线。由此逼出一个必须表态的问题：**外部测试包算包的一部分，还是包的消费者？**

按层分别回答，理由写进代码：

- **`experimentation` 算一部分**。领域文档明写它的场景测试「跟着 `experimentation` 走，未来一起搬，不重写」——测试够到上层，与包本身够到上层一样致命。
- **上层算消费者**。透过 `campaign` 测试，必然要构造它下面的层；外部测试包是这套东西唯一的装配根。**包自身的文件仍然照查**，分层要管的正是那部分。

这个豁免是检查上新开的口子，**因此配了自己的变异**：包内测试文件（`package campaign`）够到上层必须照样失败；一个目录若只剩豁免文件，判为「什么都没检查」而不是通过。

## 风险与未覆盖项

**真风险（仅观察，须说明）**：

1. **「走不到的行」只覆盖可证的那部分**。本轮能判的是「某行要求的条件是前面某行的超集」。`docs/product/design-system.md` 里举的那个例子——「近 7 天有加购」被「新客」「老客」两行合起来吃掉——**本轮判不出来**，因为那需要知道两行合起来覆盖了全体。判不出时不报，**不是判为没问题**，但运营也不会收到任何提示。`interaction-invariants.md` 把不变量 5 归在「提醒」档，而本轮**只落地了可证子集的「当场拦住」，提醒档本身未落地**，如实记为未覆盖。
2. **外部测试包的豁免是检查上的真口子**。它有明确理由、按层区分、并配了自己的变异，但它确实让上层的外部测试文件不受分层约束。若将来有人把逻辑写进那类文件，分层不会拦。

**真风险（放行后续跟进）**：

- **平局报错发生在裁决时，而不是配置时**。资源位那条线上 APP 在等，此时报错等于那次请求什么都不返回。更好的形态是建活动时就发现同位同分，但活动是各自独立创建的，构造期看不到彼此。**本轮不做**，交人工裁定。

**本次不覆盖项**：

- **执行侧**：调外部接口、回执关联、重试。投放项只产出结果。
- **幂等键**。事实 48 要求它贯穿决策→执行→回执三段，后两段本轮不存在；只做第一段无法证明那条约束。
- **事件与事件串**；业务场景 ①④⑤。
- **批量枚举执行路径**（我们找人 · 批量）。本轮只做当场决定那条。
- 指标、观测期、显著性。
- `scenarios` 层。
- 频次、退订、免打扰。
- 活动与投放项的状态机（`interaction-invariants.md` 待澄清 D1，未表态）。
- **业务回归用例**：根 `AGENTS.md` 的「当前状态：尚未建立」**进一步部分解除**——场景 ② 的人群部分（#32）与场景 ③ 的当场决定路径（本轮）已落成会失败的测试。场景 ①④⑤ 与跨层部分仍未建立。

**需要后续动作的事项**：

- 人工裁定：本轮四项自行裁定（平局显式报错、可证互斥保守、投放位需注册、留痕只记可推出的字段）是否认可。
- 人工裁定：平局是否应改为配置期发现。
- 「不臆造裁决规则」若要成为通则，须按 `mechanization-claims` 规则 6 回头复核前两层有无同型缺口。**本轮未做。**

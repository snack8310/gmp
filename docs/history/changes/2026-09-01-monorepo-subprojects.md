# 把 docs/domain 的「多 repo」表述改为单仓库多子项目

关联：issue #21

## 背景

人工裁定 `gmp-core` 是本仓库内的子项目，所有子项目都在 `snack8310/gmp` 里管理，不建独立 repo。这推翻 `system-boundaries.md` 的 B2 与 `campaign-user-stories.md` 的事实 34。

不改的代价：路线图的下一项是建 `gmp-core`。若实现落成本仓库子目录、而规格真源仍写着「独立 repo」，评估器可同时引到声明侧原文与实现侧路径，取证完整，按取证纪律必须判 `FAIL`。已关闭的 PR #14 正是死于这一类「产物与送审真源对不上」。

## 关键实现

- **只改工程边界表述，不改任何领域语义。** 依赖方向、接口的职责形状、跨边界归属、B9 的方向反转论证均未触碰——B9 在包粒度上照样成立：实验服务将来若要开放给第三方，仍需保持零依赖才搬得走。
- **B2 与事实 34 按目录既有惯例划线保留 + 注明推翻依据**，不删除。
- **把 B2 反对意见里的担心显式转为硬要求。** B2 当初选独立 repo 的理由是「在同一个 repo 里留好口子没有任何机制保证，人一忙就穿透」。该担心不随结论失效，只是换了承担方：单仓库后 repo 边界不再顺带挡住跨层依赖，故「`experimentation` 不得依赖另外两个」的固化要求由「应固化」上调为「必须固化」，并补写了数量下限断言的要求（包被改名或删除时，发现驱动的循环一次都不执行，脚本照常打印通过）。
- **本次未落地该检查**——按 [`mechanization-claims`](../memory/mechanization-claims.md) 规则 4 如实记为：**未固化，由 `gmp-core` 第一轮的 issue 承接，该 issue 尚未创建**。文档中不得称其已固化。

## 关键文件

- `docs/domain/system-boundaries.md`：定位段与「拆法」段的多 repo 表述；B2 划线推翻并转写责任；「放在单独一个 repo」改为本仓库子项目；B8 问题措辞；「内部必须按依赖方向分层」一节补入固化强度上调与下限断言要求。
- `docs/domain/campaign-user-stories.md`：事实 34 的末句划线推翻，定名部分保留。
- `docs/domain/README.md`：定位段两处、「可判定的边界」表一处、设计文档写法约定一处的 repo 措辞。

- **真风险（放行后续跟进）**：`experimentation` 的零依赖现在只剩一个尚不存在的检查兜着。在它落地前，跨层依赖穿透**不会有任何提示**。承接方式见上方「关键实现」末条。
- **本次不覆盖项**：
  1. 依赖方向检查未落地。

  3. 根 `AGENTS.md` 未改动。其「技术栈尚未确定」的表述由 issue #13 承接，与本次无关。

# 新建 docs/product，落地视觉样式体系

关联：issue #30

## 背景

[`2026-09-14-interaction-invariants.md`](2026-09-14-interaction-invariants.md) 留下的待澄清 D4 问的是：视觉样式体系放哪儿。人工裁定——新建 `docs/product/`。

按 `docs/domain/README.md` 的「可判定的边界」，配色、字体、构件形态约束的是「它内部长什么样」，属禁止侧，不能进 `docs/domain`。而在本次之前，这套取值**只存在于一份设计画布里**——画布在仓库之外，取不回来就等于没有出处，与 `docs/history/memory/` 记的「出处必须指向可被第三方独立取回的持久产物」同型。真正开始写前端时，没人能回答「那个蓝是哪个蓝」。

## 关键实现

- **新建 `docs/product/`，先写边界再写内容**。README 定义本目录写什么、不写什么、与 `docs/domain/` 冲突时以谁为准。分界线是一句话：那边回答「什么必须恒真、平台在哪一刻介入」，本目录回答「那一刻运营看到什么」。没有这条，新目录会变成什么都往里扔的地方——`docs/domain` 当初正是靠同类规则才没散掉。
- **明确出处归属**：样式取值以本目录的文档为准，设计画布、原型、将来的前端代码都是它的渲染。
- **语义色只服务于介入时点**，不做装饰。三档（当场拦住 / 提醒 / 机制保证）各自的取值与共用形状写死；绿色在本体系里只表示「平台替你守住了」，不表示「成功」「已完成」。
- **三级文字的取值被实测推翻并改掉**。原值 `#8A837A` 在纸底上实测仅 3.59:1，低于 AA 正文标准，而它正被用作 12px 次级标签。改为 `#736C63`（纸底 4.96:1、卡片 5.18:1）。**这是算出来的，不是看出来的**——凭眼睛判断，原值完全「够用」。
- **关闭 `interaction-invariants.md` 的待澄清 D4**，并修订其「边界与非目标」一节中「落点未定」的表述。
- **设计画布同步到新取值**，以保持出处与渲染一致。

## 关键文件

- [`docs/product/design-system.md`](../../product/design-system.md)：本次新增。色彩、字体、构件、版式、对比度实测值、待澄清清单。

## 风险与未覆盖项

**真风险（放行后续跟进）**：

1. **`docs/product/` 不在任何自动化检查的遍历基准内**。把这两份文档整份删掉，门禁仍会全绿。已在 README 内如实标注，不作为待办清单的装饰。可机检的近似形态有两个——同一语义色不出现两个取值、文档内引用的仓库路径存在——两者与 issue #12 的范围同族，**本轮不落地**，承接见 #12。
2. **对比度实测是一次性脚本，未入库**。按 `mechanization-claims` 规则 1 记为未固化。它这次抓到了一处真实缺陷，而人工复核（包括本 Agent 的目视判断）没有抓到——这正是它值得固化的理由。同样承接见 #12。

**仅观察**：

- 设计画布与本目录文档之间**没有任何一致性检查**。本次靠替换后计数为零来核对，下次改动若只改一边，不会有任何机制发现。画布本身不在仓库内，机检无遍历基准。

**本次不覆盖项**：

1. **不改动任何领域语义**。三档介入时点的定义仍归 `docs/domain/interaction-invariants.md`，本目录只规定它们长什么样。`docs/domain/` 的四份决策记录一字未动。
2. **不写前端框架、组件库选型、构建配置、目录结构**——仓库内尚无前端，现在写等于臆造。
3. **界面稿的逐屏版式未纳入**，本轮只到样式体系这一层。要不要纳入见 `design-system.md` 的待澄清 P2。
4. 深色模式、移动端形态均未定义，见待澄清 P1、P4。
5. **业务回归用例**：根 `AGENTS.md`「业务回归用例」一节的「当前状态：尚未建立」本轮未变动——本次是文档变更，不触及 `gmp-core`。

**需要后续动作的事项**：

- issue #12：把「同一语义色不出现两个取值」「文档内引用的仓库路径存在」纳入结构检查，并把 `docs/product/` 纳入遍历基准。
- 人工裁定：界面稿的逐屏版式是否纳入本目录（P2）。

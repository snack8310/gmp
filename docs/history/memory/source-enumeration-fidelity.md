# 从来源文本编制清单类文档的枚举保真

## 规则

- 从来源文本（需求原文、业务主线、接口清单）编制清单类文档时，必须以**来源侧**为遍历基准：拆出每个顿号分项、每个并列连词（与 / 或 / 和 / 及）两侧的项，逐项标记落到产物的哪一条。**禁止以产物为基准反向确认「看起来都覆盖了」。**
- 未被任何条目逐字承接的分项，必须显式写出「合并进第 N 条」或「判定不适用，理由 X」，不得沉默略过。
- 覆盖判定必须同时排除两种失败：
  - **丢词**：分项在产物中完全消失。
  - **复合词压缩**：多个分项被合并成一个词，字面残留但语义合并（如「渠道接入协议、连接器抽象」→「渠道连接器协议」）。仅做字面 grep 只能抓前者。
- **探针**：条目的「后果 / 说明」列若只提到该条目枚举项的一部分，即是该条目枚举有缺口的可见痕迹，必须回查来源。
- 本规则同样适用于**描述产物的送审摘要**（PR 正文、变更证据、任务卡）。**禁止在送审载体中书写计数**（断言数、用例数、条目数、段落数、行数），无论它出自工具还是手写，一律改为枚举类别或枚举条目。能枚举就枚举，枚举不会随产物增删而失真。

  该条原为「摘要中**尽量不写「共 N 段 / N 条」这类计数**；确需给出时，N 必须以产物实测为准，不得凭记忆填写」。**「尽量」与「确需时」留下的口子不足以挡住这类失效**：issue #10 的另一条路径（PR #14，已关闭）中，同一个断言总数在三份送审载体上出现三个互不相同的数字，且无一等于送审 commit 上的实测值；同一轮修复删掉计数后，下一轮又出现一处「7 项」——它在条目重编号后变成了假值，而写下它的人并未再核对。故上调为禁止。

  豁免的边界是**「计数只在执行时产生、不被转写进载体」**，不是「它出自工具」。工具运行时打印的检查项数不受约束——它每次执行都重新产生，不会与产物脱节；但把 `Assertions: <N>` 或 `全部通过（<N> 项检查）` 这类输出原样粘进 PR 正文或变更证据，它就被冻结成了载体里的计数，与手写的一样会失真，**同样禁止**。载体里该写的是退出码、被覆盖的解释器名、断言类别这类不随产物增删而变的事实。

  **等价改写同样禁止**：「断言总数为三位数」「覆盖 N 类断言」仍是计数，换个说法不改变它会失真这一点。把计数写进受版本控制的产物（日志快照、golden 文件、徽章）再由载体链接引用，也只是把冻结点挪了个位置。相关规则见 [[mechanization-claims]]。

## 原因

issue #7 中，同一类遗漏在同一份文档上连续出现五次：

| 来源 | 被吞掉的部分 | 掩盖它的条目 |
|---|---|---|
| 业务主线 f「各自的抽象模型与统一执行契约」 | 各自的抽象模型 | 只取了后半句的条目 |
| 业务主线 a「名单来源、圈选、快照与生命周期」 | 名单来源 | 其余三项逐字保留的条目 |
| 业务主线 e「分流单元、分桶算法、实验定义与指标口径」 | 实验定义 | 「分流单元」足够邻近 |
| 业务主线 c「渠道接入协议、连接器抽象、发送结果回执」 | 两项被压成一个复合词 | 「连接器」字面在场 |
| 产物自身的表下限定说明 | 第六段未被计入 | 三份送审载体都写了「五段」 |

每次都被一条「看起来相关」的东西在语义上掩盖，三轮评估器审查才逐个挖出。

第四次证明「逐字对照」不足以抓复合词压缩 —— 字面上什么都没少。第五次证明该失效模式会**从产物迁移到描述产物的摘要上**，因此规则必须覆盖摘要，且计数本身就是错误来源。

前三轮实施方均自称「已逐字对照，通过」。**纯态度型规则无效**，必须落成产物形态（分项承接表），才能被审查。

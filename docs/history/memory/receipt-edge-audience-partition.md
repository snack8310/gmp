# 活动内回执边的跨层回归不得让下一步人群与回执人重合

## 规则

- 在 `scenarios` 层为活动内回执边做跨层回归时，下一步投放项必须绑一份**与回执可能命中的人不相交、且非空**的人群定义。
- 断言要同时钉住两件事：执行到的人等于命中该边的回执人；这些人与下一步投放项自己的人群没有交集。只断言「有人被投递」或「人数大于零」不算覆盖。
- 空人群不能代替这份不相交的非空人群。空人群看起来像「没配置」，「沿边带人」和「按下一步人群枚举到零个人」会得到同一个结果。
- 本条已被用例钉住：[`gmp-core/scenarios/receiptflow_test.go`](../../../gmp-core/scenarios/receiptflow_test.go) 的串行与按回执分支。下一步分别指向 returning / new / returning，入口分别是 new / other。改成与入口同一分区时，对应用例失败。
- 类型约束做不到这一条：投放项本来就可以指向任意人群。把下一步改成与回执人相同的定义，编译照样通过。

## 原因

活动内下一步的人来自回执，不来自下一步投放项的人群枚举。若这两批人被配成同一批，枚举那份人群的实现也会把「对的人」投出去，回归全绿，走错路径不会报错。

`campaign` 包内曾用一份谁都不命中的人群挡住这件事。那能抓住「枚举到空」，抓不住「枚举到一份恰好与回执人相同的人群」。跨层装配要挡的是后一种。

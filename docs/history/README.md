# 历史沉淀说明

本目录是 AI Loop 的记忆层，分两类，用途不可互换。

| 目录 | 内容 | 由谁写 | 何时写 |
|---|---|---|---|
| `changes/` | 单次需求 / 缺陷 / 重构的**变更证据** | 主 Agent | 评估器审查通过、进入人工最终审核前 |
| `memory/` | 长期有效的**抽象记忆** | 评估器 | 评估器审查通过后，由评估器判断是否需要 |

核心区别：**变更证据写事实，抽象记忆写稳定规则。**

变更证据回答「这次做了什么、验证了什么、留了什么坑」；抽象记忆回答「以后遇到同类问题必须怎么做、为什么」。变更证据会过期，抽象记忆不应该过期 —— 一旦过期就要修改或删除。

新增抽象记忆前，先按根 `AGENTS.md` 的「约束落地优先级」判断：这条规则能否变成类型约束或一个必跑的测试？能则优先固化，不要写成散文规则。

## 变更证据格式

文件名：`YYYY-MM-DD-<短横线主题>.md`

```markdown
# <标题>

## 背景

为什么要做这次改动。一到两段。

## 关键实现

做了什么。列要点，不写过程流水账，不复述 diff。

## 关键文件

- `path/to/file.ext`：改了什么

## 验证结果

| 命令 / 检查 | 结果 | 证据摘要 |
|---|---|---|
|  |  |  |

## 风险与未覆盖项

- 真风险（放行后续跟进 / 仅观察的部分）：
- 本次不覆盖项：
- 需要后续动作的事项：
```

## 抽象记忆格式

文件名：`<短横线主题>.md`，不带日期 —— 它描述的是长期规则，不是某次事件。

```markdown
# <规则主题>

## 规则

- 一条一条列，每条都是可执行的硬约束（「必须 / 禁止 / 应当」），不是建议。
- 涉及边界条件的，写清楚边界值和判定方式。
- 已经被类型或测试固化的部分，注明固化位置，避免重复约束。

## 原因

为什么需要这些规则。写清楚不遵守会发生什么、这条规则是被什么问题逼出来的。
没有原因的规则会在半年后被当成教条删掉。
```

## 读取要求

任务入口检查阶段必须扫描本目录，且命中必须落到规则级（来源文件 + 章节 / 行号 + 是否命中 + 应用方式或不适用原因），不得只写「已读取」。详见 [任务入口检查清单](../ai-loop/task-intake-checklist.md)。

目录为空时，仍需写明检索方式与「未命中」结论。

# 样式体系

## 状态

**草稿。** 最后修订对应 issue #30。

本文档是样式取值的**出处**。设计画布、原型、将来的前端代码都是它的渲染，不是它的来源——见 [`README.md`](README.md)「取值以本目录为准」。

## 它为什么长这样

这个平台最贵的错误都**不报错**：放量用随机取样会把先进来的人悄悄踢出、决策表条件重叠没人告诉运营、回流延迟配短了全判成「没打开」、只对齐盐不对齐切法意图落空。

哪些事会静默失效、平台在哪一刻介入，是 [`docs/domain/interaction-invariants.md`](../domain/interaction-invariants.md) 的事。本文档只回答**那一刻运营看到什么**。

由此推出整套样式的一条准绳：**语义色只服务于介入时点，不做装饰。** 界面上出现红、琥珀、绿，永远只意味着一件事——这里有一条会静默失效的约束。没有「好看所以用点颜色」的位置。底色、墨色、强调色因此都压得很淡，把对比度留给那三档。

## 色彩

### 色板

**每个角色只在这里出现一次取值。** 下文与界面稿引用角色名，不再重复写十六进制——同一语义色出现两个取值不会报错，只会让两处界面慢慢长得不一样。

| 角色 | 取值 | 用在哪 |
|---|---|---|
| 纸底 | `#FBFAF7` | 页面背景。暖调 off-white，不是纯白 |
| 卡片 | `#FFFFFF` | 卡片、表格、输入框 |
| 墨 | `#1C1A17` | 主文字、主按钮底色 |
| 次级文字 | `#55504A` | 说明文字、表头 |
| 三级文字 | `#736C63` | 标签、弱提示、单位 |
| 分隔线 | `#E4E0D8` | 卡片边框、表格分隔 |
| 描边 | `#CFC9BE` | 次级按钮、输入框边框 |
| 行分隔 | `#F0EDE7` | 表格内相邻行 |
| 表头底 | `#F5F3EE` | 表格表头 |
| 弱底纹 | `#FDFCFA` | 需要区分但不该跳出来的行 |
| 中性标签底 | `#F1EFEA` | 类型标记一类的无语义标签 |
| 强调 | `#2C4A7C` | 链接、选中态、当前项 |
| 淡强调 | `#EBF0F7` | 选中态底色、状态标签底 |
| 拦住文字 | `#9B2C20` | 「当场拦住」一档的文字与圆点 |
| 拦住底 | `#FBECE9` | 同上的底色 |
| 拦住边 | `#E8C4BC` | 同上的边框 |
| 提醒文字 | `#9A6410` | 「提醒」一档的文字与圆点 |
| 提醒底 | `#FCF3E3` | 同上的底色 |
| 提醒边 | `#E8D5AE` | 同上的边框 |
| 保证文字 | `#2F6B4F` | 「机制保证」一档的文字与圆点 |
| 保证底 | `#E9F2ED` | 同上的底色 |
| 保证边 | `#BFD8CB` | 同上的边框 |

全套只有**一个**强调色。不增加第二个——多一个强调色就多一处跟语义色抢注意力的地方。

### 三档介入

这三组是本体系里唯一不能被样式偏好覆盖的部分。每一档对应 `interaction-invariants.md` 的一档介入时点。

| 档位 | 角色 | 含义 |
|---|---|---|
| **当场拦住** | 拦住文字 / 拦住底 / 拦住边 | 配置保存不了，必须改 |
| **提醒** | 提醒文字 / 提醒底 / 提醒边 | 配置合法，但后果是静默的 |
| **机制保证** | 保证文字 / 保证底 / 保证边 | 形状本身使违反不可表达，不靠运营记得 |

**三档共用同一个形状**：左侧一个直径 10px 的实心圆点，右侧一行加粗短句 + 一段说明。短句说「会怎样」，不说「你错了」——例如「这件事不会报错：第 3 行的人已经被前面的行吃掉了」，而不是「条件重叠」。

**「机制保证」这一档不是警告**。它出现在运营做对了的地方，告诉他平台替他守住了什么。绿色在本体系里只有这一个用途，不表示「成功」「已完成」一类的状态。

### 对比度

实测值（WCAG 2.1 相对对比度），左右两列都写角色名，以便逐行重算核对：

| 前景 | 背景 | 比值 |
|---|---|---|
| 墨 | 纸底 | 16.63:1 |
| 次级文字 | 纸底 | 7.64:1 |
| 三级文字 | 纸底 | 4.96:1 |
| 三级文字 | 卡片 | 5.18:1 |
| 强调 | 淡强调 | 7.71:1 |
| 拦住文字 | 拦住底 | 6.59:1 |
| 提醒文字 | 提醒底 | 4.54:1 |
| 保证文字 | 保证底 | 5.51:1 |

全部达到 AA 正文标准（4.5:1）。

三级文字的取值原为 `#8A837A`，实测仅 3.59:1——不达标，而它正被用作 12px 的次级标签。已改为现值。**这是实测发现的，不是设计时想到的**：凭眼睛看，前一个值在纸底上完全「够用」。

## 字体

| 用途 | 字体栈 |
|---|---|
| 中文与界面 | `'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', system-ui, sans-serif` |
| 西文标号与区块标题 | `Newsreader, Georgia, serif`（字重 300） |
| 标识、数字、份号、算法版本 | `'IBM Plex Mono', monospace` |

**中文走系统字，不拉远程 CJK 字体。** 一套中文字重动辄几 MB，而运营平台是天天开着的工具，首屏代价直接落在每天的使用上。西文那两套是按需加载的小体积字体。

**等宽的用途是防误读，不是装饰**：分流标识、份号、算法版本、金额与人数都用等宽——这些值会被逐字比对、被复制粘贴、被写进工单。

| 层级 | 字号 / 字重 | 行高 |
|---|---|---|
| 页面标题 | 28 / 600 | 1.2 |
| 区块标题 | 16 / 600 | 1.4 |
| 卡片标题 | 14 / 600 | 1.4 |
| 正文 | 13–14 / 400 | 1.75 |
| 次级说明 | 12 / 400 | 1.7 |
| 标识与数字 | 11–13 等宽 | — |
| 大数字 | 20–30 / 500 等宽 | 1.1 |

## 构件

**圆角只有两个值**：控件 3px，卡片 4px。**不使用阴影**——层级靠线与底色区分。理由是这是一个信息密度高的工具，阴影会在密排时把每一块都推得离页面很远，读起来更累。

| 构件 | 形态 |
|---|---|
| 主按钮 | 高 34，底 `#1C1A17`，字 `#FBFAF7`，横向内边距 18 |
| 次按钮 | 高 34，底 `#FFFFFF`，边 `#CFC9BE`，字 `#1C1A17` |
| 危险按钮 | 高 34，无底色，边 `#E8C4BC`，字 `#9B2C20` |
| 状态标签 | 高 24，圆角 3，横向内边距 10，字号 12 |
| 引用芯片 | 高 24–28，边 `#CFC9BE`，等宽字。用于「分流 E · 第 2 份」这类跨子项目的引用 |
| 对照组占位 | 高 24，**虚线边** `#CFC9BE`，字 `#736C63`。虚线表示「它在系统里存在，但什么都不做」 |
| 卡片 | 边 `#E4E0D8`，圆角 4，内边距 22–28 |
| 表格 | 表头底 `#F5F3EE`，行间 `#F0EDE7`，单元格内边距 15/18 |

**图标一律用描边式内联 SVG**，16/20/24 栅格，同一种笔触。不使用 emoji 或符号字体——它们在不同系统上长相不一，而这套界面里图形常常携带语义。

## 版式

- 页面顶栏高 52，含产品名与一级导航，当前项用 2px 墨色下边框。
- 主区左右内边距 32，区块之间间距 24–28。
- 区块标题左侧带一个 `Newsreader` 的两位序号（`01`、`02`），字号 13、色 `#736C63`。它是给密集页面提供的锚点，不是装饰性编号。
- 并排块用 grid + `gap`，不用外边距拼接。

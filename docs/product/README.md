# 产品设计文档

本目录描述**运营看到的东西长什么样**：样式体系、界面形态、交互表达。

## 与 `docs/domain/` 的关系

两个目录切的是同一件事的两面，分界线是一句话：

| | 回答什么 | 例 |
|---|---|---|
| [`docs/domain/`](../domain/) | 什么必须恒真、**平台在哪一刻介入**、谁负责什么 | 「回流延迟不得短于回流粒度，当场拦住」 |
| 本目录 | 那一刻**运营看到什么** | 「当场拦住这一档用红，输入框描红，并说清不管它会发生什么」 |

**`docs/domain/` 是规格真源，本目录不是。** 两边冲突时以那边为准，并同步修订本目录。本目录不得定义、改写或复述那边的语义——三档介入时点叫什么、各自意味着什么，是那边的事；本目录只规定它们长什么样。

反过来也成立：配色、字体、构件形态不进 `docs/domain/`。那边的「可判定的边界」把「它内部长什么样」划在禁止侧，样式与框架用法、部署形态同类。

## 取值以本目录为准

样式取值可能有多处渲染——设计画布、原型、将来的前端代码。**出处是本目录的文档，其余都是它的渲染。**

理由与 `docs/history/memory/` 记的同型问题一致：指向一个取不回来的东西等于没有出处。设计画布在仓库之外，链接可能失效、可能被改、可能只有部分人能打开；真正开始写前端时，能回答「那个蓝是哪个蓝」的必须是受版本控制的文本。

## 这里不写什么

- **前端框架、组件库选型、构建配置、目录结构**——仓库内尚无前端，现在写等于臆造。
- **领域语义**——见上方分界线。
- **界面稿逐屏的版式**。本目录目前只到样式体系这一层；要不要把界面形态也纳进来，没有定过。

## 门禁覆盖

**本目录不在任何自动化检查的遍历基准内。** `test/docs/consistency_check.py` 只扫 `docs/domain/` 与 `docs/history/changes/`——把本目录整份删掉，门禁仍会全绿。

这是如实标注，不是待办清单的装饰：本目录当前的正确性完全靠人工核对。承接见 issue #12。

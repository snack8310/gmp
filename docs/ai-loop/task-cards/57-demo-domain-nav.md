# 任务卡：前端 Demo 按领域组织导航

- 关联：issue #57
- 类型：新需求开发；等级：小任务。仅改一个独立前端 Demo，不改核心领域语义、外部接口或存储格式。

## 背景、目标与范围

现有入口按「人群管理 → 运营沙盘」安排，实验对象的管理散落在两处，观众容易把演示流程误解成三个子项目的职责划分。目标是让受众、实验、运营并列展示各自对象，在最后的组合页演示跨域装配和播放。

范围内：`frontend/demos/operations-flow/` 的页面、导航、交互、样式、导出、测试和 README；本任务卡及变更证据。非目标：接入 `gmp-core`、指标界面、可编活动流程图、改动 #55/#45 裁定。替代方案「只改旧 tab 的名称」被否决，因为实验创建仍会留在受众和画布里，不能解决归属混淆。

## 验收标准

1. 顶层仅受众、实验、运营、组合，顺序固定；默认受众；宽屏左侧导航、窄屏顶栏导航，支持领域深链和 `aria-current="page"`。
2. 受众可维护人群，引用实验域已保存项；本页不编辑实验比例或实验定义。
3. 实验页可创建、查看、改名及删除未被引用的实验；兼容现有 localStorage；固定 45/45/10 比例，说明稳定分配、染色和放量。
4. 运营页仅有活动、投放项一动作、活动流程边三张概念卡，说明 #44/#55 关系；没有播放按钮。
5. 组合页保留人群选择、沙盘、播放、流程实验节点、统计和场景；「编辑此人群」返回受众。
6. README「操作」按领域写，原「口径与边界」保留；始终标明「模拟数据 · 不会真实触达」。
7. 前端全部 Node 测试、改动模块 `node --check` 与导出测试通过。

## 影响面与入口检查

- 影响文件：`index.html`、`style.css`、`app.mjs`、`audience-ui.mjs`、新实验 UI 模块、`audience.mjs`、`export.mjs`、相应测试、README。调用者为页面入口和离线导出器；数据夹具 `DEFAULT_EXPERIMENTS` 与现有缓存版本保持兼容。
- 外部系统：GitHub 写入 issue/分支/PR；浏览器 localStorage 读写同一演示命名空间；无其他外部系统写入或网络运行依赖。展示数据都是构造数据。
- 高风险：逐项核对通用 1–7 和项目清单 1–17，均未命中；只改变独立前端展示与演示对象操作，不改变 core 语义、协议、持久化结构或多实现契约。对外破坏性变更：否。
- 人工确认：用户当前请求已明确导航、页面内容、边界和开 PR 方式；无需额外实施前确认。最终由人工放行 PR。

## 风险三档

- 真风险（阻断）：当删除仍被人群引用的实验时，缓存会产生孤儿引用；删除必须拒绝且给出提示。当删除组合当前引用的人群时，组合会悬挂旧对象；删除后应切换到仍存在的人群或清空。切页时若播放不停，会在隐藏的组合页继续运行；切离组合应暂停。
- 真风险（仅观察）：原生浏览器的布局和焦点可能与处理器替身不同；需浏览器验证，做不到则列为缺失验证。
- 伪风险：不会向真实用户触达，因为 Demo 没有渠道接口或 `gmp-core` 调用，不做生产联调。
- 未讨论项：哈希深链进入编辑态时是否保留未保存草稿？交评估器攻击，当前采用保留草稿且显式导航。

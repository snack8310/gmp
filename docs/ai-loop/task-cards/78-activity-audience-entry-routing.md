# 任务入口检查：活动受众入口与流程路由模型对齐

关联：[#78](https://github.com/snack8310/gmp/issues/78)

## 任务分类

- 类型：新需求开发（核心模型语义对齐）
- 等级：大任务
- 判断依据：同时触及 `gmp-core`、活动管理 API V1、前端演示与领域规格；改变活动、受众、实验臂及活动流程的核心关系，并破坏性调整 API 请求体。

## 问题本质

- 用户表面请求：确认活动演示流程是否符合“一个活动只有一个受众”，再调整 core 模型。
- 要解决的真实问题：现有活动保存多个入口受众，每个投放项也各自绑定受众；实验臂与回执边因此都表现成“投放项受众”，不能保证单一活动入口、实验分配与后续回执推进各司其职。
- 硬约束：活动选一个普通人群组或一个已发布实验人群包；实验臂决定起始投放路径；后续活动内步骤仅由动作回执边推进，带着原回执 UID 执行；保留当前 3D 流程画布、动作合同、回执与实验分桶语义；本地演练不触达真实用户。
- 更本质的候选方案：只调整演示文案，继续让投放项分别选择人群。否决：core 仍可构造多个独立受众，无法由类型与接口阻止模型漂移。
- 成功标准：core 和演示 API 都只有一个活动级入口受众；活动流程显式映射入口人群/实验臂到起始投放项；投放项只描述动作；沿回执边只执行原 UID；已确认业务场景均能由模型表达。

## 范围

- 范围内：`gmp-core/audience` 的单受众选择类型；`gmp-core/campaign` 的活动、投放项、起始路由、决策和执行；跨层业务回归；管理 API V1 和 3D 演示数据/操作；领域/API/演示文档及破坏性变更记录。
- 非目标：真实渠道、生产持久化/鉴权、多实例；改动作/回执/分桶算法合同；改画布 SVG 绘制与交互；增加「组合」实体或菜单。
- 影响面：`gmp-core/audience`、`gmp-core/campaign`、`gmp-core/scenarios`、`management`、`frontend/demos/operations-flow`、`docs/domain`、`docs/api`。
- 外部系统读写影响：无。本地演示 API 只读写进程内构造数据；不连接真实渠道、数据库、队列或缓存。

## 风险点（三档）

### 真风险

- **阻断**：若实验包有一个臂既未路由到起始投放项、又未显式标记为对照，则它会被静默漏掉；以构造期校验和对照回归阻断。
- **阻断**：若回执边进入目标时未沿用上游 UID，或丢失派生 execution key 与 placements 关联，则下一步对象或归因会偏离；以 `Treatment` 无独立人群字段和跨层 UID/key/placements 回归阻断。
- **阻断**：若前端/API/core 对单受众和入口路由采用不同合同，则配置可能被静默覆盖或无法演练；以共享 JSON fixture/HTTP 客户端回归阻断。
- **放行后续跟进**：管理 API 仍为进程内演示状态；重启恢复种子，不作为生产持久化。

### 伪风险

- 活动唯一入口不妨碍普通人群与实验包跨多个活动复用；共享资产本身继续留在受众库。
- 对照臂没有投放项并非漏配，因为业务场景 ② 明确要求保留零投放对照；实现通过独立、显式的 `Control` 状态区分，不引入长期留置型 Holdout。
- 继续使用现有画布 renderer 不会改变流程语义；本次只更换画布节点绑定的数据模型。

### 未讨论项

- 活动级 `Rollout` 目前是另一份 `audience.Group`，但被规格定义为活动放量门槛而非独立业务入口。实现需保留既有单调放量语义，并由评估器攻击“入口与放量被误合并或放量绕过”的边界。
- 实验包的多个臂允许映射到一组还是多组起始投放项：本次按通用能力支持一个臂映射到多个并行或决策候选项，并由评估器核对展示位互斥与实验归因。

## 约束落地方式

- 本次新增约束：是。
- 类型 / 接口固化：`audience.Selection` 用封闭构造函数表达“单组或单个实验包”；`TreatmentSpec` 删除 `Who`；`CampaignSpec` 要求一个 Selection 与一个 Flow；Flow 有显式入口路由与对照状态。
- 自动化检查：构造时拒绝入口漏配、重复路由、非所选受众的组、未知节点、冲突入口和无效回执边；场景回归固定活动内回执 UID 语义。
- 规则文档：同步修订领域事实中与新裁定冲突的段落，并记录 V1 破坏性变更。

## 评估器重点

- 攻击实验包中漏臂、重复臂、对照臂和一个臂并行多投放项的边界。
- 核对入口受众 gate、决策表条件、Rollout 与活动级回执边之间的顺序和归因。
- 查证回执目标没有独立人群字段，并且只执行回执 UID、保留派生 execution key 关联与 placements。
- 核对管理 API 的完整性保护、前端旧字段移除、画布渲染复用及 V1 breaking change 记录。
- 根据实际命令审查 core、管理 API、演示及文档验证证据，并判断是否新增抽象记忆。

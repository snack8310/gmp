# 任务卡：在活动内容中恢复并复用既有 3D 流程画布

- 关联 Issue：#76
- 类型：新需求开发；等级：大任务。
- 入口检查：2026-11-01。当前活动详情只显示投放项表和流程边表；旧版 3D SVG 沙盘在 #74 导航调整中被整体移除。用户指出回退后流程图仍缺失，并明确要求复用旧页面的 3D 流程图，不另造一套画面。

## 问题本质

- 表面请求：当前活动版本没有 3D 流程图。
- 真实问题：运营不能在活动上下文里看到受众入口、投放项和活动流程边的整体关系，也无法用既有图形界面做本地演练。
- 硬约束：活动是组合承载体；受众和实验仍为可跨活动复用的共享资产；活动详情不能出现独立「组合」菜单；演练仅使用构造数据，不连接真实渠道；核心 `style.css` 不改；必须复用 Git 历史中旧版 3D SVG 沙盘的绘制和交互实现（可将其重构为模块），不得设计替代画布。活动主流程是先选择/创建受众入口，再在活动画布中装配投放项与回执边。
- 更本质候选：直接恢复旧「组合」页签和脱离活动的沙盘。否决：会重新引入用户已明确拒绝的独立组合对象；应把原图形组件放回活动内容并绑定当前活动。
- 既有实现取证：`frontend/demos/operations-flow/app.mjs`、`index.html`、`model.mjs` 在提交 `41acbb9` 中含旧沙盘；提交 `6f789e9` 删除其 HTML、播放逻辑与模型。

## 范围

- 范围内：活动详情内的 3D 流程图；从画布选择共享入口人群并跳转到共享受众库新建人群；普通组稳定 ID 与显示名同步到本机管理 API 目录；在画布内装配/移除活动入口，在活动工作区创建、编辑、删除投放项与创建、编辑、删除回执边；活动入口与流程边更新须拒绝基于过期列表的整份覆盖；使用当前活动的引用、投放项和活动流程边展示图形；复用旧画布的投影、节点外观、视角控制和本地播放方式；保持管理 API 的进程内状态边界；更新 API 与操作说明。
- 非目标：单独「组合」实体/菜单、全新画布视觉系统、真实渠道触达、生产执行、持久化、多实例、改动核心 `style.css`。
- 外部读写：活动、动作目录和人群目录只读/写本机管理 API 当前进程；受众与实验仍使用当前浏览器演示存储；不访问生产数据库、渠道或个人信息。

## 验收标准

- 从活动列表进入活动，在活动内容中可直接看见旧版 3D 画布；无需「组合」菜单。
- 可从共享目录选择受众作为活动入口；可从画布进入受众库新建普通人群，返回活动后可选作入口。
- 入口列表与投放项、回执边均绑定当前活动；创建投放项后可在画布看见节点并编辑，列表保留删除入口；可新增、编辑回执边的起点/终点/条件并删除，编辑保留原边 ID；重复快速提交不应覆盖；过期活动页更新入口或边时服务端返回冲突且保留最新状态；无投放项的活动可先保存受众入口。
- 画布的绘制风格与交互复用 `41acbb9` 的 3D SVG 沙盘实现；不得以表格、静态卡片、全新 2D 图或新建视觉规范替代。
- 本地演练始终明确标示“本地演练，不会真实触达”；禁止真实发送或生产分桶。
- 现有活动、投放项、受众引用和活动流程校验语义不被静默放宽；服务端写失败时不得显示保存成功；已被活动入口或投放项引用的人群不能删除。
- 不修改 `frontend/demos/operations-flow/style.css`；画布额外样式（如确有必要）使用独立 CSS。
- 活动列表、活动编辑、投放项 CRUD、共享资产路由继续可用，旧版独立组合入口不恢复。

## 高风险项与人工确认

- 已确认的产品范围：用户明确要求「活动详情内以受众作为流程入口，在 3D 画布里构建投放项目并启动运营」，随后明确“启动”仅指本地演练。
- 命中项目高风险 #1（活动流程/边）与 #4（受众引用语义）；若改动 management API 请求/响应，再命中通用标准 #2。实施需复用现有模型/校验，禁止由画布自行定义边条件、入口或执行行为。
- 对外破坏性变更：否；不删除或改写现有 HTTP 字段。

## 风险（三档）

### 真风险

- **阻断**：当图形把活动 ID、受众引用或边绑定到错误活动时，运营会误读路径；必须用活动切换、刷新和深链覆盖当前上下文。
- **阻断**：当演练路径与活动流程边分叉时，会误导配置；演练只能从当前活动边集合驱动，且不能把演示结果呈现为真实执行。
- **放行后续跟进**：管理 API 重启会恢复构造种子；本次沿用既有演示边界，并在画布标明。
- **仅观察**：Safari、Firefox、真机触屏尚未覆盖，需在证据中说明。
- **仅观察**：「已走回执边」演练统计按总边数和播放进度估算，不是按每条构造样本的实际路径计数；分支负载不同可能让数字与图上路径不一致，不用作业务执行口径。
- **仅观察**：活动 API 只保存入口引用 ID 与名称；受众定义规则和模拟样本仍在浏览器本地。服务端重启后，当前浏览器重新加载会同步其保存的人群引用。

### 伪风险

- 复用旧图不会恢复「组合」概念：画布位于活动详情内部，路由与数据均以活动为上下文。
- 演练数据不连接真实渠道，因此真实消息发送风险不在当前实现路径内。

### 未讨论项

- 一个活动包含多个入口人群或不同实验臂时，图形需按实际引用区分入口；评估器重点检查并行入口、不同引用以及空边活动是否被正确显示。
- 旧沙盘中的播放模型是否能表达当前活动所有动作回执：若无法从既有模型/契约证明，不得用新规则猜测，应将其作为演练能力限制清楚展示。

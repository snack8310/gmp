## 问题本质

- **用户表面请求**：写 `campaign` 层。
- **要解决的真实问题**：`interaction-invariants.md` 的不变量 5、9、14 目前只是断言——决策表条件重叠没人告诉运营、同活动两个投放项抢同一位会同时命中一个人、抢位输了不留痕就无从查起。三条共用同一条执行路径（场景 ③ 的当场决定），本轮就切这条。

- **已考虑并否决的更本质解法**：见 issue #34「A 是不是唯一方式」表。
- **成功标准**：issue #34「验收标准」每条能被一个命令或一个测试判定，且在 CI 上真跑。

## 范围

- **范围内 / 非目标**：见 issue #34。**特别地：执行侧、幂等键、事件串、批量枚举路径全部在非目标内**；不修改 `docs/domain/` 的任何语义。
- **影响面**：新增 `gmp-core/campaign/`；`gmp-core/audience/` 新增一个可证互斥的判定；`gmp-core/internal/arch/` 的分层表增行并同步扩变异。

  **实施中发现并修订**：本卡初稿写的是「`experimentation` 不改动」。判定两份人群定义可证互斥，前提是它们引用的是**同一个分流修订**——而修订是否相同取决于盐，盐只有 `experimentation` 知道且不外露。故须向该层补一个只读判定方法。**这是新增能力，不改动既有语义**，`experimentation` 的现有行为与测试均不变。此处如实回写，不让任务卡与实际落点分叉。
- **外部系统读写影响**：无。

## 约束落地方式

- **本次是否新增约束**：是。
- **能否由类型 / 接口固化**：**能，且优先**——裁决结果是一个值而非一次调用；同活动内抢位守卫在构造期；动作参数必填由构造期校验。
- **能否由自动化检查固化**：**能**——依赖方向由既有检查扩展承载并配变异；决策表三件事由用例承载。
- **若仍不能**：U2 的「一般情况下的人群覆盖判定」不可机检，本轮按保守判定处理并写明理由。

## 评估器重点

- **需要重点攻击的反例**：
  1. **被吃掉的行判定报了「没问题」而实际被吃掉**（U2）——保守方向若反了，这条守卫就变成了假保证。
  2. **演练模式在 `campaign → audience → experimentation` 这条链上有断点**——任一段漏传即静默染色。
  3. 同活动内抢位守卫是否真在**构造期**拦住，而不是留到裁决时。
  4. 「可证互斥」的判定是否把不可证的情形误判为可证。
  5. 放量闸门是否作用于**整个活动**，而不是逐个投放项——挂错层会让各实验臂放量不同步。
  6. 留痕是否覆盖**全部**输家，而不只是最接近的那个。
  7. 分层表增行后变异是否同步扩了。
- **需要检查的历史规则**：上方清单逐条，含判定不适用的两条。
- **需要核对的验证证据**：必跑命令真实退出码；依赖方向变异实证；CI 的 `headSha` 等于送审 SHA。
- **需要判断是否新增抽象记忆**：候选——「规格没说的裁决规则，正确做法是显式报不可裁决，不是挑一个看起来合理的」。由评估器裁定。

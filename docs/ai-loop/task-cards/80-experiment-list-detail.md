# 任务入口检查：实验列表与详情的本地可操作页面

关联：[issue #80](https://github.com/snack8310/gmp/issues/80)。

## 任务分类

- 类型：新需求开发。
- 等级：大任务。页面、路由、浏览器缓存与受众预览跨模块变更；实验分流与染色具有静默失配风险。

## 问题本质

- 用户表面请求：实验页采用标准列表与详情，完成实验模型的页面端。
- 真实问题：当前卡片页只能看到固定比例和只读染色说明，不能通过实验身份进入可操作详情，也不能验证比例调整后旧、新分配如何变化。
- 硬约束：本轮仅实现浏览器本地、构造数据的前端交互；不接管理 API，不改 `gmp-core`。实验经受众人群包间接被活动引用。旧缓存不得静默丢失。
- 已考虑但否决的解法：仅增加比例输入框，沿用卡片页。它无法集中展示运行态、染色与引用关系，也容易让其他页面继续使用固定比例。
- 成功标准：实验列表与独立详情可导航；比例及染色设置在本地可操作，受众预览使用同一配置；旧缓存兼容，演示不冒充 Core 或生产能力。

## 范围

- 范围内：实验列表、详情、新建、路由；构造用户的本地分配与染色示意；浏览器缓存兼容；受众预览联动；文档与前端回归。
- 非目标：管理 API、Core 实验服务改造、生产染色存储、真实指标、真实用户和渠道。
- 影响面：`frontend/demos/operations-flow/`、其运行说明、设计文档和本次变更证据。
- 外部系统读写：仅浏览器 `localStorage` 的演示命名空间读写；不访问数据库、缓存服务、队列或真实渠道。GitHub 仅用于 issue、分支和 PR 协作记录。

## 最小验证集

- 前端单测：列表、详情、深链、无效 ID、创建、运行态、比例校验、染色旧值保留、新值分配、只读预览、旧缓存读取与损坏失败关闭、受众预览一致、发布包代际。
- 命令：前端 `node --test`、改动模块 `node --check`、导出检查、`python3 test/docs/consistency_check.py`、`git diff --check`。
- 浏览器：桌面与窄屏浏览实验列表、详情、比例与染色示意、刷新及前进后退；明确无真实染色。
- 不覆盖：生产持久化、多设备同步、Core/API 联调、真实实验指标、真实分桶压力。

## 风险点（三档）

### 真风险

- **阻断**：当比例改了而受众预览仍用固定比例时，同一构造用户会在不同页面显示不同臂。以统一分配函数及跨页回归阻断。
- **阻断**：当只读预览写入模拟染色，或合法比例更新移动已染色用户时，页面会错误展示 Core 语义。以只读与首次记录回归阻断。
- **阻断**：当升级缓存时丢失旧人群或实验，用户的本地构造配置会消失。以旧版本迁移及原始缓存不覆盖断言阻断。
- **放行后续跟进**：浏览器本地模拟与 Core 运行时不是同一个服务；后续 API 接入须单独做契约与一致性验证。

### 伪风险

- 无生产染色存储不构成本轮缺陷，因为用户明确选定前端先行；页面必须如实标为本地构造演示。

### 未讨论项

- 旧缓存没有染色策略字段，能否依据旧演示“不写染色”行为迁移为关闭，交设计确认和评估器攻击。
- 比例变化对已发布人群包不应推进实验代际；页面及测试须核对这一点。
- 染色开关在实验开始后是否允许切换，设计按 Core 定义不可运行中修改处理，需人工确认。

## 约束落地与评估器重点

- 构造期/保存边界校验比例和染色配置；本地格式版本化与测试承接旧数据规则，不新增散文禁令。
- 评估器重点攻击跨页分组一致性、染色首次记录、旧缓存损坏、停启用后包失效、演示标识是否清楚，并核对真实命令结果。

## 2026-11-03 用户反馈：实验页视觉对齐

- **标题 / 类型 / 等级**：实验列表与其他页面样式不一致；缺陷修复，小任务。用户在本地查看 `#experimentation` 后直接指出此问题。
- **背景与目标**：实验列表使用独立青绿色、较大圆角和阴影，活动列表使用表格、仓库强调色及无阴影样式。让实验列表与现有活动列表的标题、按钮、搜索和行展示保持一致，详情与新建页沿用同一套样式取值。
- **范围**：实验页面标记与专属 CSS；不改实验数据、缓存、路由、API、Core 或活动页面。复用现有 `section-heading`、`primary-link`、`campaign-table` 与 `docs/product/design-system.md` 的色板和构件取值。
- **验收标准**：实验列表呈现标准表格列；标题、链接、状态和按钮使用现有设计变量；卡片无阴影，圆角与活动页一致；搜索、新建、详情、空态及 390px 横向滚动可用；活动与受众页样式不受影响。
- **真风险**：阻断——重排列表后搜索或详情链接失效；用前端回归和浏览器操作验证。放行后续跟进——本任务不解决此前独立评估器判定的重复染色记录与活动演练说明问题，issue #80 仍不得请求人工合并。
- **伪风险**：纯视觉对齐不改变 Core 分桶语义或本地缓存格式，故不命中实验高风险 #5 与持久化标准 #4；不投入该方向的额外联调。
- **未讨论项**：用户未指定逐像素目标，以同仓库活动列表与受众页面的当前样式及 `docs/product/design-system.md` 为可取回基准；交评估器检查是否仍有独立青绿色、阴影或明显不一致的控件。
- **入口检查**：本次无新增外部系统读写、接口或破坏性变更，无实施前高风险人工确认。已读取历史记忆与活动列表、产品样式相关变更；最小验证为前端测试、语法、导出、文档门禁、diff 检查和桌面/390px 截图对照。独立只读评估器仅审视觉增量，不覆盖既存 `FAIL` 裁决。

## 2026-11-03 用户反馈：详情页与共用尺寸

- **标题 / 类型 / 等级**：实验详情页沿用标准样式并抽取共用尺寸；缺陷修复，大任务。用户明确指出详情仍不一致，并提出“抽离一组标准的尺寸，其他页面不要自己造”。
- **问题本质**：仓库已有 `docs/product/design-system.md`，但前端的活动、受众、实验样式各自写尺寸；实验详情又单独做了一张重复标题卡。需让共用尺寸成为 CSS 变量和复用构件，而不只把实验页调成相似颜色。
- **范围**：共享 `style.css` 的尺寸变量与面板构件；实验详情、新建和列表使用这些构件；活动和受众既有面板使用同一尺寸值。同步相关测试与视觉验证。不改领域语义、浏览器缓存、路由、管理 API 或 Core。
- **非目标**：逐项重构所有历史 CSS、改业务内容或修复此前整体评估的两个阻断项。
- **验收标准**：活动、受众、实验详情的面板内边距、圆角、标题字号与控件尺寸从同一套变量取得；实验详情不再重复大标题卡；实验页专属 CSS 不再硬编码同类尺寸；桌面和 390px 截图无明显错位或整体横向溢出；原交互与前端回归通过。
- **影响面 / 外部读写**：共享 CSS 可影响活动、受众和实验三个页面；本次不新增任何外部系统读写，既有浏览器本地模拟写入行为不变。
- **真风险**：阻断——共享尺寸影响活动或受众布局，导致窄屏溢出或表单不可用；用三页面桌面与窄屏截图、关键操作和全量前端回归验证。放行后续跟进——先前重复染色与活动演练说明的整体 `FAIL` 仍不解除。
- **伪风险**：此轮不改变实验配置或缓存含义，不需要重新验证 Core 的分桶结果；样式变化可由回退 CSS 恢复。
- **未讨论项**：样式文档的页面标题 28px 与当前内页区块标题 23px 属不同层级；以既有 `h1` 与 `.section-heading h2` 区分，评估器攻击是否混用。移动端未定义完整规范，以既有 390px 页面表现为回归基线。
- **高风险 / 人工确认**：通用标准 #7 命中，因为共享 CSS 覆盖多个页面。用户本次明确要求共用尺寸，视为实施前确认；只调整视觉，不扩大到实验领域高风险 #5。
- **历史与验证**：已读 `docs/product/design-system.md`、相关活动/受众样式、`docs/history/memory/` 与近期视觉变更。最小验证为前端测试、语法、离线导出、文档门禁、diff、活动/受众/实验桌面与 390px 视觉及交互对照。独立只读评估器重点核对变量确被多个页面复用，且没有用新覆盖层掩盖重复值。

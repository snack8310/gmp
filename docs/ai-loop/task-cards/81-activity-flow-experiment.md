# 任务入口检查：活动流程实验节点（前端本地草稿）

关联：[issue #81](https://github.com/snack8310/gmp/issues/81)、[已确认设计](../../superpowers/specs/2026-11-03-activity-flow-experiment-design.md)。

## 分类与问题本质

- 类型：新需求开发；等级：大任务。
- 表面请求：活动明细单独添加实验，放在活动流程里，与受众实验分开。
- 真实问题：当前活动只在受众入口借实验人群包分组，无法表达“已进入活动、到达某个步骤后再实验分流”。这两种分组时点与复用范围不同，不能用同一个活动受众选择器冒充。
- 已比较并否决：仅给活动加实验库链接无法创建流程节点；把已有实验人群包臂重新画在流程中仍只能入口分组；活动私有实验定义会重复实验库的比例与策略，用户已选择引用共享定义。

## 目标、范围与边界

- 目标：活动详情可新增、编辑、移除引用实验库定义的流程实验节点，在任意有效路径插入并配置 A/B/对照分支；画布与本地构造演练使用同一草稿。受众侧与每个流程节点按独立身份稳定分组。
- 范围：`frontend/demos/operations-flow/` 的独立草稿存储、合成流程、活动实验面板、3D 画布、实验库引用保护、测试、操作说明及本次证据。涉及活动侧和实验侧展示，但不改管理 API 或 `gmp-core`。
- 非目标：管理 API 活动流程协议、Core 分桶/染色实现、真实执行与实验指标、跨设备同步、生产数据迁移。
- 外部读写影响：读取现有本机管理 API 活动与实验库浏览器数据；新增独立版本化浏览器草稿键的读写，含仅构造 ID 的本地模拟染色；不新增对管理 API 的写请求，不访问真实渠道。存储日志只记录操作名与结果，不打印构造 ID 或原文。
- 对外破坏性变更：否。现有管理 API、`gmp-audience-demo-v1` 与活动流程格式均不升级；新增草稿键由本轮前端独占。

## 验收标准

1. 从普通人群活动入口、已保存回执边、尚无后续的回执出口和已有实验分支均可插入流程实验节点；实验人群包对照臂的无投放路径不可插入。空流程可先从受众入口占位添加。
2. 节点引用运行中的实验库定义，比例与染色策略只在实验库编辑；活动实验面板可编辑位置及三组去向，画布显示专属节点和标名分支。每组恰有一条去向，可到投放项、后续节点或结束；不能形成环、悬空路径或静默不可达的现有投放项。
3. 本地演练只给到达节点的构造用户分组；同一 UID 在受众引用和每个流程节点的分配互不影响，同一节点重复到达只记一次人。首次模拟染色稳定；只读预览零写入；比例更新只影响未染色者。
4. 停用/缺失定义、删除目标投放项、API 流程变化、损坏草稿、浏览器写入失败均有明确状态，不能在无效图上继续演练或静默重连。
5. 草稿刷新后可恢复；活动受众选择、现有 API 入口/回执边保存及受众实验数据不因本轮操作变化。页面明确标注草稿只在本浏览器，未进入管理 API/Core。全局实验库仍可管理定义。
   活动实验列表中的名称、内部 ID、位置、分组去向和状态说明沿用活动页面的文字层级，不能退回浏览器默认段落字号。
6. 前端回归、离线导出、语法、文档门禁与桌面/390px 实际浏览器流程通过；独立只读评估器对本任务给出 `PASS` 后进入人工最终审核。

## 高风险项与人工确认

| 命中项 | 原因 | 处理 |
|---|---|---|
| 项目 #1：活动流程节点/边语义 | 新实验节点与分支改变本地流程的路径解释 | 合成图验证、场景回归、独立评估；API 图不变 |
| 项目 #5：实验定义、分桶、染色 | 同定义跨受众与流程使用，但要求独立稳定分组 | 复用同一前端分桶函数，节点专属分配键和染色记录；只读预览测试 |
| 通用 #4：浏览器持久化结构 | 新增版本化草稿键及模拟染色 | 独立命名空间、严格读取、失败关闭、回滚说明 |
| 通用 #7：跨活动、受众和实验页面 | 活动流程引用实验库，删除与停用影响草稿有效性 | 跨页与刷新回归、引用保护 |

**实施前人工确认：已确认。** 用户于 2026-11-03 依次确认“任意步骤可添加”“节点引用实验库共享定义”“受众与流程各自独立分组”，随后批准设计稿并要求按设计实施。旧受众侧“活动内分流是例外”的历史偏好不排除本能力；本期不改变 Core 规格，只形成前端可审阅的行为。

## 风险点（三档）

### 真风险

- **阻断**：当画布显示实验节点而本地演练仍走原 API 边时，同一配置在页面内自相矛盾。合成图与演练必须共用一份草稿路径结构，并测试插入、合流及结束。
- **阻断**：当同一实验定义被受众与流程引用时共用染色键，会使两件独立的事相互改变分组。测试同 UID、同定义、不同节点身份下的隔离与首次记录。
- **阻断**：当 API 投放项或回执边变化时，草稿自动接到其他节点会误导运营。保存锚点并失败关闭，显示修复提示。
- **放行后续跟进**：管理 API 与 Core 尚不支持此节点，真实活动不可按草稿执行；页面必须显式标明。后续需独立版本化接口与业务回归任务。

### 伪风险

- 本轮不迁移真实染色或生产活动数据；新增键只存构造样本及流程草稿，不能把“生产数据回填风险”作为本轮阻断，但须检验浏览器损坏数据不覆盖原文。

### 未讨论项

- 不同标签页并发编辑草稿不具备服务端原子性；本地演示只保证当前页面内不覆盖首次记录，评估器检查文案没有暗示生产并发保证。
- 已发布实验人群包的对照臂必须保持无投放；评估器攻击它是否被错误地允许插入后续实验。
- 同一定义多节点使用时，指标如何跨活动/节点聚合属于后续 Core/API 设计；本期不得展示真实指标口径。

- 最小验证：前端单测含草稿格式、隔离分组、图验证、路由与页面操作；`node --test frontend/demos/operations-flow/*.test.mjs`、修改模块 `node --check`、离线导出、`python3 test/docs/consistency_check.py`、`git diff --check`；桌面与 390px 浏览器新建、改线、演练、刷新、停用、损坏状态。

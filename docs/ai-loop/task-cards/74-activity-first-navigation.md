# 任务卡：活动优先的演示工作区导航

- 关联：issue #74
- 类型：新需求开发；等级：小任务。仅改独立前端 Demo 的导航与路由，保留已有活动 API、共享资产存储和业务语义。

## 任务分类与问题本质

- 表面请求：最左侧显示活动列表；选中活动后才进入受众、实验、运营等工作区。
- 真实问题：当前受众、实验、运营、组合平铺在顶层，活动列表藏在运营页内，导致用户先按领域而不是按活动进入工作。
- 更本质候选：只把「管理活动」入口移到侧边栏，保留四个顶层领域。否决：活动仍不是工作区父级，用户进入受众或实验时仍无法判断当前活动上下文。
- 成功标准：活动列表是最外层入口；选中一个活动后显示受众、实验、运营、组合四个子页签；活动和子页签均可深链、刷新并遵循浏览器历史。

## 已确认的硬约束

- 用户确认：人群定义、实验定义及实验人群包仍是可跨活动复用的共享资产。
- 活动 ID 仍取自管理 API；运营子页按路由中的活动 ID 读写，不改变 API 契约。
- 组合随活动工作区显示；不新增活动与受众/实验之间的持久化关联，不改变既有模拟语义。
- 不改 management、gmp-core、活动流程边、人群圈选、实验分桶、存储格式、权限或真实触达。
- 所有数据仍为构造数据；网页不调用生产服务。

## 范围

范围内：`frontend/demos/operations-flow/` 的 HTML、样式、路由、交互、离线导出、自动化测试与 README；本任务卡。保留现有活动 CRUD 与投放项功能，更新页面导航以使用所选活动上下文。需要时兼容带活动 ID 的旧运营深链。

非目标：活动级人群/实验隔离；组合模拟与管理 API 的业务装配；任何后端、领域模型、外部契约或持久化格式变化。

## 验收标准

- 最外层侧栏能显示并选择活动；无活动选择时显示活动列表或明确空态，不显示脱离活动的领域工作区。
- 选中活动后显示受众、实验、运营、组合子页签，当前活动和当前页签都有明确选中态。
- 所选活动 ID 和子页签可深链；页面刷新、浏览器前进/后退和域间切换后仍显示同一活动和域。
- 运营子页读写路由指定的活动；列表、详情、编辑、创建、删除和错误态不串到其他活动。
- 受众、实验、实验人群包仍引用原共享存储；在不同活动之间切换不复制、不迁移、不重命名存储键。
- 旧活动详情深链可被正确解释或明确引导到等价新路由；未知活动 ID 显示未找到且可返回列表。
- 桌面和窄屏均可操作活动列表与子页签；键盘焦点和 `aria-current` / `aria-pressed` 状态正确。
- 全部前端测试、改动模块语法检查、离线导出和文档一致性检查通过；使用浏览器走查主要路径与窄屏布局。

## 影响面与外部系统

- 影响文件预计为 operations-flow 的 `index.html`、独立 `activity-navigation.css`、`app.mjs`、活动路由/控制器相关模块、相应测试与 README；核心 `style.css` 不改，不得改 `management/` 或 `gmp-core/`。
- 浏览器现有活动 CRUD 继续读写本机 management API；本次只改变路由上下文，不增加 API 请求语义。
- 受众与实验继续读写现有 `gmp-audience-demo-v1` 浏览器存储命名空间；本次不迁移或删除数据。
- GitHub 已写入 issue #74；代码留在 `feat/74-activity-first-navigation` 分支；无其他外部写入。

## 风险三档

- **真风险（阻断）**：若在活动切换或浏览器历史恢复时丢失活动 ID，运营子页可能对错误活动发起改名、删除或投放项写入；必须以路由活动 ID 驱动控制器，并以不同活动 ID 的回归用例验证。
- **真风险（放行后续跟进）**：窄屏活动数量增多时，侧栏可能挤压内容；本轮通过响应式布局走查，若极窄设备仍有问题记录为后续支持范围。
- **真风险（仅观察）**：跨浏览器差异未覆盖；自动化与可用 Chrome 走查通过后，保留 Safari / Firefox 未测说明。
- **伪风险**：人群和实验未改为活动私有不是遗漏；用户已确认它们是共享且可复用资产。
- **未讨论项（评估器攻击点）**：旧 `#campaign/activities/{id}` 活动详情链接与新活动层级路由的映射、无效百分号编码、活动列表为空及创建后默认子页签，需在实现和路由测试中显式核对。

## 最小验证集与评估器重点

- 命令：`node --test frontend/demos/operations-flow/*.test.mjs`；改动 `.mjs` 执行 `node --check`；运行 `python3 test/docs/consistency_check.py` 和 `git diff --check`；生成离线 HTML 并验证其内联脚本/样式。
- 必补回归：活动选择和路由活动 ID 一致；子页签切换不丢上下文；浏览器历史、刷新和深链；无效/未知活动；旧活动详情深链；创建活动后导航；共享受众/实验存储未改变；离开组合后暂停播放。
- 人工验证：桌面侧栏、窄屏活动切换与页签、键盘焦点、`aria-current`；若运行环境不可用，明确记录缺失证据。
- 不覆盖：生产服务、真实渠道、跨浏览器矩阵、业务级活动—人群—实验装配。
- 约束落地：路由 ID 经统一解析后传给活动控制器；共享资产不引入新存储键；以回归测试固化，不新增仓库规则。
- 评估器应攻击：活动切换时旧异步响应覆盖当前活动；新建/删除后当前选中项失效；旧哈希路由与特殊 ID 编码；窄屏侧栏可达性；共享资产行为或组合暂停回归；导出 HTML 与模块清单一致。

# 任务卡：以活动承载投放项与共享资产入口

- 关联：issue #74
- 类型：新需求开发；等级：大任务。虽然代码范围限于独立前端 Demo，但活动路由与 CRUD 事件的并发/执行顺序控制命中高风险标准 3，按任务入口清单的大任务规则分级。

## 任务分类与问题本质

- 表面请求：全局要有活动、受众、实验三个入口；用户进一步澄清「组合」不应作为单独概念，活动本身承载一组能力，投放项是活动内列表。
- 真实问题：现 Demo 的独立组合沙盘与活动投放项、活动流程没有数据关系，却作为活动第二页签出现，并允许受众跳入沙盘，造成组合是另一业务对象的误解。
- 更本质候选：活动作为 Campaign 容器，选择活动后直接展示活动详情、投放项清单和现有可选活动流程；受众和实验分别维护跨活动共享列表，活动投放项引用统一人群目录。否决：把独立沙盘改造成真实活动模拟会把构造数据与活动流程语义混在一起，触及核心模型和流程边；将投放项提升为一级菜单会与活动下挂多个投放项的领域关系冲突。
- 成功标准：活动、受众、实验各有全局入口；选择活动后详情直接呈现投放项列表和可选活动流程，不再有组合页签/沙盘入口；共享受众与实验仍按统一目录供投放项引用，实验通过受众资产间接进入活动。

## 已确认的硬约束

- 用户确认：人群定义、实验定义及实验人群包仍是可跨活动复用的共享资产。
- 用户于 2026-11-01 补充澄清：受众、实验也各自是一级菜单并有独立列表；活动内部需提供共享资产的创建或引用入口。该澄清已在本轮修改前同步 Issue 与本任务卡。
- 用户于 2026-11-01 进一步明确：不单列「组合」概念；一个活动代表一组能力，投放项是活动内容列表。此澄清已先同步 Issue 与本任务卡，再开始代码修改。
- 人群配置与人群组由受众域持有；实验定义由实验域持有；活动通过统一人群引用目录引用人群组或实验人群包臂。实验仍经人群配置/人群包间接进入活动，不新增活动到实验定义的直接关系。
- 活动 ID 仍取自管理 API；选中活动后直接展示对应活动详情，不改变 API 契约。
- 活动详情保留活动信息、投放项清单及现有活动流程关系；不改活动流程边语义。
- 不再显示独立组合页签/沙盘及「用于组合演示」资产入口；旧组合深链回到活动详情，不引入新的活动—模拟数据关联。
- 不改 management、gmp-core、活动流程边、人群圈选、实验分桶、存储格式、权限或真实触达。
- 所有数据仍为构造数据；网页不调用生产服务。

## 范围

范围内：`frontend/demos/operations-flow/` 的 HTML、独立样式、路由、交互、离线导出、自动化测试与 README；本任务卡及 Issue #74。保留活动 CRUD、投放项 CRUD、活动流程展示和共享资产管理；选择活动后直接进入活动内容，移除组合页签、独立沙盘入口和受众页组合引用操作。旧组合深链兼容回到活动详情。

非目标：活动级人群/实验隔离；新增活动到实验定义的直接关联；把独立沙盘接入活动流程或实现真实模拟；修改任何后端、领域模型、活动流程边语义、外部契约或持久化格式。

## 回滚方案

回滚本分支对 operations-flow Demo 的前端提交即可恢复原有导航；本任务不涉及后端、API 契约或持久化数据迁移。

## 验收标准

- 最外层一级菜单提供活动、受众、实验入口；三个模块分别展示各自列表，并有明确的选中态和空态。
- 活动列表选择活动后直接进入活动详情；不再显示运营/组合内部页签，当前活动有明确选中态。
- 活动详情直接展示活动信息、投放项列表和既有活动流程关系；投放项仍是活动下级对象，不新增投放项一级菜单。
- 独立组合页签、沙盘 HTML 和启动逻辑均从管理界面移除；受众列表不显示组合引用入口；旧 `compose` 路由回退到活动详情或活动列表。
- 人群一级列表维护共享人群配置/组及实验人群包；实验一级列表维护共享实验定义。跨模块打开、返回和刷新不改变共享身份或存储。
- 活动投放项创建/编辑流程可引用统一目录中可用的人群组或实验人群包臂，并能从活动上下文前往人群/实验一级列表新建资产；实验须经人群配置或实验人群包被间接引用，不新增活动—实验直接持久化关系。
- 模块路由与活动 ID 可深链；页面刷新、浏览器前进/后退及模块切换后恢复预期位置。旧 `compose` 深链不再显示独立页面。
- 活动内容路由读写指定的活动；列表、详情、编辑、创建、删除和错误态不串到其他活动；离开某次活动渲染后，其旧表单提交和删除控件不得再写入或改变当前路由。
- 活动详情中的「编辑活动」和「＋ 添加投放项」保留链接语义，并使用现有 `primary-link` 按钮样式。
- 受众、实验、实验人群包仍引用原共享存储；在不同一级模块或活动之间切换不复制、不迁移、不重命名存储键。
- 旧活动详情及领域深链可被正确解释或明确引导到等价新路由；未知活动 ID 显示未找到且可返回活动列表。
- 桌面和窄屏均可操作一级菜单、资产列表、活动列表与活动详情；无运营/组合内页签或组合沙盘入口；键盘焦点和 `aria-current` / `aria-pressed` 状态正确。
- 全部前端测试、改动模块语法检查、离线导出和文档一致性检查通过；使用浏览器走查主要路径与窄屏布局。

## 影响面与外部系统

## 风险三档

- **真风险（阻断）**：当活动直达详情或旧 `compose` 深链仍落到失效路由时，创建/编辑可能不可达或写入错误活动；必须按活动 ID 驱动活动控制器，并验证资产库返回、投放项表单和浏览器历史仍回到正确活动。
- **真风险（放行后续跟进）**：窄屏活动数量增多时，侧栏可能挤压内容；本轮通过响应式布局走查，若极窄设备仍有问题记录为后续支持范围。
- **真风险（仅观察）**：跨浏览器差异未覆盖；自动化与可用 Chrome 走查通过后，保留 Safari / Firefox 未测说明。
- **伪风险**：人群和实验未改为活动私有不是遗漏；用户已确认它们是共享且可复用资产。
- **未讨论项（评估器攻击点）**：旧 `#campaign/activities/{id}` 与领域哈希映射、旧 `compose` 深链回退、无效百分号编码、活动/资产列表为空、资产新建返回位置及活动内实验间接引用关系，需在实现和路由测试中显式核对。

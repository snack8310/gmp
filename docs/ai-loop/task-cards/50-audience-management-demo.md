# 人群管理与运营沙盘联动

关联 issue #50；分支 `feat/50-audience-management-demo`。新需求开发，小任务。

## 背景与本质

用户希望把人群管理与已认可的运营流程 Demo 结合。真实问题是理解「定义谁符合条件 → 复用定义 → 在沙盘观察」而非建设执行引擎。只画静态稿不能验证保存、取消与人数一致性，因此采用独立浏览器原型；不引入框架或后端。

## 目标、范围与验收

- 在 `frontend/demos/operations-flow/` 增加人群列表、命名、编辑、取消、保存、引用，使用构造数据。
- 单一来源（App 或预置白名单）加国家、用户生命周期、未活跃天数范围；条件按 AND 求交。非法配置阻止保存；零匹配合法并明确解释。
- 实时预览人数与匿名模拟样本来自同一个筛选函数。保存定义至本浏览器 localStorage，不保存名单；存储不可用或损坏时降级并提示。
- 沙盘引用已保存定义，切换人群或修改被引用定义后暂停、重置；草稿不污染已保存对象或沙盘。
- A/B 默认关闭；开启时稳定展示 A/B/对照组，明确属性资格与随机分配不同。对照组不经过触达渠道，终态计数与总人群守恒。
- 保留播放、暂停、重播、时间轴、视角旋转、低动态偏好；响应式、键盘可操作。
- 导出自包含 HTML，不依赖外部网络、真实账号、个人数据或生产服务。

## 非目标与影响面

不修改 `gmp-core`、生产模型、领域规格、真实渠道、执行记录、染色或分桶实现；不建设多用户同步或统计显著性工具。外部系统影响：没有网络读写，唯一写入是本浏览器隔离的演示定义缓存。源文件来自同一仓库，未跨仓库复制。

## 入口检查与人工确认

高风险通用项中的核心语义、外部契约、执行顺序、业务持久化、权限、跨实现一致性与跨服务均不命中：本次是独立展示，不改变业务能力。项目清单中的人群与分桶项不命中生产风险边界：演示条件及展示专用算法不接核心、不产生业务记录、不被业务调用。没有对外破坏性变更。

用户已于 2026-10-25 明确同意创建 Issue、独立分支及 Draft PR；不自动合并，不接真实数据。展示方向来自「帮我构建一个人群管理的 demo，可以结合刚才的 demo」；最终交互验收仍待确认。

## 风险

- 真风险（阻断）：当筛选、预览与引用口径不一致时会显示错误人数；当取消写回或存储加载失验时会污染定义；当对照组被计为成功时会误解实验。以纯函数、输入校验与测试验证。
- 真风险（仅观察）：本地缓存不跨浏览器同步，关闭存储后刷新丢失会话修改；界面显式说明。
- 伪风险：真实触达或生产数据迁移不存在；不投入生产联调。
- 未讨论项：小屏编辑布局、键盘焦点与重复打开/取消、已引用定义更新后的重置交给独立评估器攻击。

## 2026-10-25 用户确认后的范围修订（替代前述实验开关方案）

用户明确要求：人群编辑包含「圈选条件」与「可勾选的 A/B 实验」；实验为独立可复用组件，带实验引用的人群也能复用。随后确认画布不能取消继承的人群实验，但可额外增加实验，并明确同意修改。Issue #50 已同步。

- 人群定义保存规则和可选 `experimentId`；实验注册表独立保存稳定 ID 与名称。Demo 固定 45/45/10 比例，编辑名称不改变分配；同实验 ID、同模拟用户在不同引用处保持同组。
- 人群编辑器内选择、新建、改名实验；画布通过同一复用选择组件配置额外实验，不复制另一套分桶。
- 画布继承实验只读，不可取消或替换，修改入口返回人群编辑。无继承实验时，额外实验作用于整个人群；有继承实验时，额外实验仅作用于 A 或 B 分支，独立显示实验名称与该分支分母。
- 删除策略闸机，池直接展示直接触达或 A/B/对照出口。主、副对照均不触达；副实验不改变主实验成员身份。
- 仅支持一个画布额外实验，不建设通用图引擎。额外配置只保留当前会话，不修改人群定义；切换引用或保存被引用人群时清空额外配置以避免隐式套用。
- 本地演示缓存兼容此前版本；损坏或孤立引用明确提示并降级。无生产迁移。
- 新增回归：实验复用/改名、引用有效性、旧缓存兼容、继承只读、同 ID 不重复随机、分支分母、主副对照守恒、关闭额外实验不影响继承、编辑取消。

此修订仍只影响独立前端展示，不变更 `gmp-core`、业务契约或生产语义。新增真实风险（阻断）：当继承可被画布覆盖或副实验误改主分组时会误导用户；以不可编辑显示、独立配置和模型测试防止。原生浏览器证据仍由独立评估器补充，不把已运行的替身测试当作原生交互验收。

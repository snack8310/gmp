# gmp-core README 分层状态校正

关联 Issue [#84](https://github.com/snack8310/gmp/issues/84)；分支 `docs/84-gmp-core-readme-status`。文档治理，小任务。

## 任务入口检查

### 任务分类

- 类型：文档治理。
- 等级：小任务；只改一份项目 README，不改变代码、接口、领域语义或外部行为。

### 问题本质

- 用户表面请求：修正 `gmp-core/README.md` 中层级状态和未覆盖说明。
- 真实问题：README 仍把 `audience`、`campaign`、`scenarios` 写为未建立，但当前主线已包含这些包及其实现 / 测试；“本轮未覆盖”还把整层一概列为未建立，容易让读者误判 Core 现状。
- 硬约束：只修正与当前主线不符的状态和范围说明；不得把已有内存实现表述为完整领域能力或生产能力；活动流程实验节点仍是浏览器本地草稿，不得写成 Core 能力。
- 更本质方案：不扩写完整能力总览，也不为迎合 README 去改 Core；本任务解决的是文档事实漂移。
- 成功标准：各层状态能对应当前代码和场景回归；未覆盖项准确表达剩余缺口；不暗示领域规格全部实现。

### 范围与影响面

- 范围内：更新 `gmp-core/README.md` 的依赖分层状态和未覆盖项。
- 非目标：不改 Go 代码、接口契约、领域规格、分层门禁、管理 API 或前端行为；不补 Core 功能。
- 外部系统读写：无数据库、缓存、消息队列、渠道或生产系统读写。GitHub Issue #84 已创建并回读核对；本地文档变更不调用外部服务。

### 风险三档

- 真风险（仅观察）：若把“已有包”写成“能力完整”，读者会误以为领域范围已全部落地；通过限定到当前实现和测试范围处理。
- 伪风险：本次文档修正不会改变运行行为，因为不改代码或接口。
- 未讨论项（评估器重点攻击）：各层“已建立”可能被读成规格完整；评估器核对措辞是否仅表示当前有实现，且明确保留场景覆盖与 Core/API 接入缺口。

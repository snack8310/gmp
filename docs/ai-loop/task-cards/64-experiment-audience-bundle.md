# #64 实验人群包 core 最小闭环任务卡

## 任务分类与本质

- 类型：新需求开发；等级：大任务。跨 `experimentation`、`audience`、`campaign`、`scenarios`，命中高风险与公开契约变更。
- 表面请求：发布、引用、停用实验人群包。真实问题：现有臂由调用方松散拼装，缺少共同身份和失效边界，旧活动可能继续使用已作废的臂。
- 硬约束：包和组属受众；分配和染色属实验；活动公开入口挂组；第 N 份仍为普通条件；运行参数可调但加载逻辑不可运行中变更；停用、修订使旧包永久失效。
- 已否决的更小方案：仅让活动共享 `audience.Definition` 无法证明发布身份、完整臂集合或停用传播，不符合 AQ1、AQ2。
- 成功标准：issue #64 验收标准 1–9 均由构造边界与本机真实回归证明。产品澄清四项已拍板，不重开。

## 验收标准

1. 发布有稳定身份的包及完整臂组，能按包和组身份查询；不挂投放项的对照臂也存在。
2. 发布前拒绝零值、缺身份、来源或分流/修订不一致、份号越界、重复或缺臂，以及缺少对应「第 N 份」条件的臂。
3. 活动投放项、决策表与活动级放量公开入口接收组；多个活动可引用同一发布臂，放量仍只在活动级。
4. 各臂稳定互斥，枚举与单人判定一致；决策和执行保留活动、投放项、分流及逐臂实际份号。
5. 运行中可校验更新比例和白名单；白名单按分流键优先于新随机，已有染色先于白名单；包和臂不中断。
6. 运行中拒绝加载组件逻辑修订；非运行组件不得被新活动有效挂接，旧引用无法继续展示或触达；发布不要求运行中，旧包不复启。
7. 分流停用或修订使包和臂强制不可用；运行参数调整不触发此传播。
8. `scenarios/` 用例走通发布、多活动复用、多臂求值和执行、停用后新旧引用失效；原对照组、触达、同位互斥与推送不占 Slot 回归保留。
9. 本机格式化、构建、vet、全量单测与跨层回归、文档一致性和 diff 检查真实通过；变更证据记录破坏性迁移、风险、未覆盖项及回滚边界。

## 范围、影响与非目标

- 范围内：分流组件运行态及参数路径；受众组与包的构造、发布、查询、失效；活动受众挂接迁移；跨层回归；本任务卡和变更证据。
- 非目标：生产持久化、前端发布台、指标查询双视图 UI、旧包复启、强制各臂基础筛选一致。
- 仓内调用方：`gmp-core/audience/`、`experimentation/`、`campaign/` 的 Treatment、决策表行、活动放量、决策、执行、服务及测试夹具；`scenarios/` 与 `cmd/gmp-demo/`。逐个编译迁移。
- 外部读写影响：不新增生产外部系统读写；现有来源读取、染色写入、执行留痕写入继续通过现有端口。内存包及运行态只在进程内读写；本期无生产数据迁移。

## 破坏性变更与兼容安排

**活动侧公开挂接入口从直接接收 `audience.Definition` 改为接收人群组；继续传入裸 Definition 的调用将无法编译或构造失败。** 影响 `TreatmentSpec.Who`、`Row.When` 和活动级 `CampaignSpec.Rollout` 及其访问器、仓内装配和测试。仓外 Go 调用方数量未知；「本仓库外无依赖」无证据，**需人工确认**。

迁移方式：先以来源与筛选构造 `audience.Definition`，再构造单组；实验臂则从已发布包按份号取组，传给活动入口。当前未发布稳定版本与外部调用清单，仓内一次性迁移且不保留裸配置重载；若有仓外调用方，需其同步升级。兼容期暂定无，版本化及废弃计划需人工最终确认。等价 CHANGELOG 见本任务的 `docs/history/changes/2026-10-28-experiment-audience-bundle.md`。

## 风险三档

- 真风险·阻断：当分流停用/修订后旧组仍可求值或沿回执边执行时，会继续触达旧臂；测试新旧引用与边路径。运行参数若覆盖既有染色，会改变历史归因；逐键验证。归因份号若恒定，会错记各臂；逐臂对比不同预期值。
- 真风险·放行后续跟进：进程内状态重启不保留，生产持久化后续另行设计；双视图指标查询与 UI 后续实现。
- 真风险·仅观察：仓外调用方未知，在合入前人工确认。
- 伪风险：受众需要另建分桶。现有实验服务已负责稳定分配，受众只保存发布对象并委托求值，无须另建。
- 未讨论项：同一进程多服务实例间的运行态共享尚无生产存储要求；交评估器攻击是否存在跨实例绕过。回执边在停用后是否可能继续旧引用，交评估器重点攻击并以失败关闭实现。

## 最小验证集与约束落地

- 必跑：`gofmt -l .`、`go build ./...`、`go vet ./...`、`go test ./...`、`go test -count=1 ./...`；仓根 `python3 test/docs/consistency_check.py`、`git diff --check`。
- 必补测试：包构造各非法形态与发布查询；运行参数、染色不覆盖、加载逻辑守卫；停用/修订后的新旧引用；跨活动逐臂执行归因；既有场景持续回归。
- 必查边界：对照臂存在、枚举与判定相同、活动级放量不下移、推送不占 Slot、同位展示互斥、`experimentation` 零依赖。
- 替代证据：无。未覆盖：生产持久化、多实例同步、仓外编译、正式指标视图与浏览器 UI。
- 新约束优先由 `Group` 类型、包构造器、实验组件运行态 API 固化；不能在类型层证明的动态停用与染色优先级由测试固化，不新增散文规则。

## 评估器重点

对抗性检查旧 `Campaign`/`Treatment` 引用停用后的决策、批量投递和回执边；尝试用不同修订、越界或缺份号构造包；确认白名单不覆盖已有染色；核对每臂实际份号和零依赖；核对本机命令证据及破坏性变更载体一致性，并判断是否需要新增长期抽象记忆。

# 实验列表与详情：本地可操作页面设计

关联 [issue #80](https://github.com/snack8310/gmp/issues/80) 与[任务入口检查](../../ai-loop/task-cards/80-experiment-list-detail.md)。本设计待用户批准；批准前不修改产品代码。

## 意图与边界

运营从「实验」一级菜单先看到实验列表，再进入某个实验的独立详情，在一个页面上理解身份、状态、比例、染色策略和关联的人群包，并能用构造用户观察比例调整的影响。本轮只完成浏览器本地演示，后续另做管理 API 与 Core 接入；页面任何地方都不得暗示它写入生产染色或真实实验定义。

## 方案选择

| 方案 | 得到什么 | 代价 |
|---|---|---|
| 可操作的本地实验页（用户已选） | 列表、独立详情、比例与染色配置、构造样本预览和本地保存形成闭环 | 浏览器演示逻辑须与 Core 规则核对，后续接 API 时替换本地数据层 |
| 仅建列表与详情结构 | 可先审页面层级，代码和迁移较少 | 比例仍无法验证，染色依旧停留在说明文字，解决不了本次困惑 |

## 页面与导航

- `#experimentation` 是列表：名称与稳定 ID、运行态、A/B/对照比例、染色策略、已发布包引用数和「查看详情」。提供搜索、新建、空态。
- `#experimentation/{id}` 是详情：返回列表、实验名称与稳定 ID、运行/停用操作、当前分流比例、染色设置、构造用户预览、引用它的人群包。未知或格式错误的 ID 给出明确「未找到」和返回入口。刷新、浏览器后退/前进保持页面与选中对象。
- `#experimentation/new` 是新建页：名称、A/B/对照比例、是否染色均须明确输入；初始为非运行态。创建成功进入详情。编辑名称在详情完成，身份不随改名改变。
- 从活动或受众进入实验时保留现有 `return` 目标；进入详情和返回列表也保留它。一级导航始终高亮「实验」。
- 列表使用活动列表已有表格与按钮视觉语言；详情沿用活动详情的标题、信息块与表单层级。窄屏表格允许横向滚动，操作控件可换行，键盘焦点可见。

## 分流与染色交互

- 比例输入采用整数百分比，范围含 0 与 100，三臂合计必须等于 100。创建时录入初始比例；实验运行中可调整比例，保持 A/B/对照三臂结构不变。更新不推进实验代际，因此已发布包不因调比例失效。停用后的结构修订不在本期表单中提供。
- 染色策略在创建时选择「记录首次分配」或「不记录」；选择不得留空。实验运行后不可切换这一策略。已有浏览器实验按其旧实现的事实迁移为「不记录」，因为旧演示只计算固定哈希、没有染色记录。
- 详情的「只读预览」对构造 ID 计算当前臂：若有已存模拟染色，优先显示该结果；没有则按当前比例预测，**不写入**记录。单独的「模拟首次分配」操作才写入本浏览器的模拟染色；再次操作同一构造 ID 保持首次结果。比例更新后，已记录者不换臂，未记录者按新比例分配。
- 页面展示本地模拟染色记录数、按臂分布和示例构造 ID；不显示真实用户、真实指标或“生产已染色”文案。记录只使用生成的 `SIM-*` ID，不允许输入真实标识。浏览器演示哈希仍标明是演示实现，不宣称与 Core 算法或生产结果逐人相同。
- 受众预览统一读取实验对象的当前比例和已有模拟染色，不再调用固定 45/45/10 的独立口径，也不写记录。活动流程画布仍是独立的构造路径演练；页面需明确它不代表这份实验的实时分桶结果。
- 白名单、算法版本与盐、实验指标和放量配置本轮不提供操作入口。详情应准确说明尚未接入这些 Core 能力，避免展示看似可用的假控件。

## 数据与兼容

- 沿用浏览器演示命名空间 `gmp-audience-demo-v1`，内部格式升至新版本，保存实验比例、染色策略及模拟染色记录。仅保存构造 ID 和实验臂；日志只输出操作名、结果，不输出用户 ID、载荷或浏览器存储内容。
- 旧格式的实验比例已由现有代码明确固定为 45/45/10，且无染色写入；据此迁移，不改实验 ID、名称、运行态、代际、受众与已发布包。读取旧格式时先在内存完成整份校验，不立即重写原缓存；首次成功保存后写新版本。
- 新版本字段缺失、非法比例、重复或未知染色记录、未知版本均失败关闭，保留原始缓存并显示当前会话回退提示。保存失败不显示成功。页面返回隔离副本，避免外部代码直接改内部状态。
- 首次写入新版本前，在独立备份键保存读取到的旧版原文；备份失败则不升级。旧版导出页面不能读取新版本，回滚时须恢复备份后再使用旧版页面。本地缓存格式因此按破坏性变更登记，记录在 `CHANGELOG.md`，不把“仅是演示”当成免除兼容说明的理由。
- 本地模拟染色只承诺当前页面内重复分配不覆盖首次结果；浏览器存储不提供跨标签页原子写入保证。跨标签页竞态不作为 Core 染色合同的验证证据，后续接 API 时由服务端存储实现承担。
- 停用/重新运行继续使用现有代际规则，旧包不得因重新运行复活。比例更新与模拟染色记录不更改代际。

## 验证与交付

- 数据层测试：合法与非法比例、已染色优先、单页面重复分配不覆盖首次结果、只读预览零写入、比例更新的新旧用户结果、停启用代际、旧缓存迁移与损坏失败关闭。
- 页面测试：列表、详情、新建、搜索、深链、未知 ID、后退、从活动返回、表单失败状态、受众预览一致、导出页面可运行。
- 浏览器走查：桌面与窄屏完成列表→详情→调整比例→模拟分配→再次调整→确认旧记录不动；刷新后状态仍在当前浏览器。运行前端测试、语法检查、文档门禁与导出检查。
- 变更证据记录读写影响、测试命令、已知演示边界与回滚方式。独立只读评估器给出结论后，再进入人工最终审核；不自动合并。

## 不做与失效判断

- 不连接真实分流服务、生产数据库或真实渠道，不增加管理 API，也不修改 `gmp-core` 领域语义。
- 若详情可编辑比例但受众预览仍固定，或只读预览写入染色，则本设计未达成。
- 若旧浏览器数据被升级过程覆盖、已有包因调比例失效，或页面把本地模拟记录称作真实染色，则本设计未达成。

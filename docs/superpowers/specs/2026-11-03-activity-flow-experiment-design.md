# 活动流程实验节点：前端本地设计

**状态：用户已于 2026-11-03 确认，关联 issue #81。** 本设计承接用户反馈：活动明细应能单独添加实验，并把实验放进活动流程；受众中的实验是另一种使用方式。本轮仍按此前确认的边界先完成前端，暂不改管理 API 和 Core。

## 意图与既有边界

- 活动受众继续回答“谁进入活动”：活动只选一个普通人群组或一个已发布实验人群包。受众侧引用实验时，可以把分好的组跨活动复用。
- 活动流程中的实验回答“到达这一步的人走哪条路径”：它是独立的流程节点，只有到达节点的用户才分组；节点可以插在入口、投放项的某条回执路径之后，或另一实验节点的分支之后。
- 两种使用方式都从实验库读取名称、比例、运行态和染色策略，但**分配身份独立**。即使引用同一个实验定义，同一构造用户在受众和流程中也分别分组；同一活动的两个流程节点也分别分组。页面明确显示“共享配置、独立分组”。
- 当前管理 API 的活动流程只有受众入口与“投放项 → 投放项”的回执边，没有实验节点。因此本轮的活动实验只存为本浏览器的**流程草稿层**，图形和本地演练合并展示 API 流程与草稿；不把草稿伪装成已保存到管理 API 的活动配置。

## 方案选择

| 方案 | 得到什么 | 取舍 |
|---|---|---|
| **流程节点引用实验库定义（用户已选）** | 实验库仍是比例和策略的单一配置位置；受众与流程各自决定何时、对谁使用它 | 每个引用位置须有独立分配身份；API 尚不能保存节点，前端须明确本地草稿边界 |
| 活动私有实验定义 | 活动内配置与受众实验完全隔离 | 同一份比例和策略会在活动里重复建立；用户已选择引用共享定义 |
| 把现有受众实验臂当作流程实验 | 不需新节点 | 分组只能发生在入口，无法在任意步骤添加，也混淆“谁进入”和“之后走哪条路径” |

## 页面与操作

1. 活动明细保留独立的“活动受众”区，只显示已选受众和受众库入口。其下增加“活动实验”区：列出本活动的流程实验节点、所引用的实验定义、插入位置、各组去向与本地草稿状态，提供“＋ 添加实验”。没有节点时给出空态。
2. 添加时先从实验库中选一个**运行中**的定义，再在当前流程的一条路径上选择插入点。插入点可为受众入口连线、某个投放项的指定回执连线、已有实验节点的一条分组连线，或投放项某个尚无后续步骤的回执出口；空流程也提供受众入口占位供先加实验。实验人群包的对照臂必须保持无投放，不提供在其结束路径上插入实验的操作。仅在所选路径上到达的用户进入实验。名称、比例和染色策略只读展示，修改入口指向实验库详情。
3. 新节点有独立稳定 ID。配置 A 组、B 组、对照组的去向：现有投放项、后续流程节点，或“在此结束”；对照组可以跳过被测动作并在后续公共路径汇合。保存前验证目标存在、无环、每组恰有一条去向，且原路径被节点替代后没有悬空连线。若实验分支使 API 中仍存在的投放项变得不可达，阻止保存并指出需重新连接或先移除该投放项，不自动删除它。
4. 活动流程画布显示与投放项不同形状的实验节点及带组名的三条分支。点选节点可查看引用身份、比例、各组去向和本地分组预览，并可编辑位置、连接或移除。入口仍由活动受众决定；实验节点不成为第二个活动受众，也不在投放项上新增受众字段。
5. 页面明确区分“管理 API 已保存的活动流程”和“仅此浏览器的实验草稿”。实验节点与分支的保存按钮写“保存到此浏览器”；管理 API 的入口/回执边保存按钮维持原语义。草稿未接入 Core，不参与真实执行。

## 分组、失效与演练

- 本地演练仅使用构造 ID，沿合成图走到实验节点时才按该节点分组。节点的分配键由实验定义 ID、活动 ID、节点 ID 共同确定；受众侧既有分组记录不读写此键。两个节点即使引用同一定义也不共用分组记录。
- 同一构造 ID 即使经多个入口或回执路径多次到达同一实验节点，该节点只分组一次；“分组人数”按不同构造 ID 计，“路径到达次数”另计。后续公共投放项可以承接多个分支，但合流不重新分组。
- 实验定义选择“记录首次分配”时，首次模拟结果只写入本浏览器的该节点记录；随后比例调整不移动已记录的构造用户，新到达者按新比例分配。“不记录分配”时仅按节点专属键稳定预测。只读预览不写染色。
- 实验停用、删除或比例结构不兼容时，节点标为“引用不可用”，禁止继续保存该节点或运行包含它的本地演练；不回退成随机分组。实验库删除操作须检查流程草稿引用；若跨标签页变化造成缺失，也按不可用处理。
- API 入口/回执边变化导致某个插入点或去向不再存在时，草稿标为“需要重新连接”，保留原文供用户修复，不自动改接到别的投放项。移除节点不触碰受众配置、实验库定义或 API 流程。
- 本地演练展示每组人数与实际到达的后续节点；它只验证页面草稿的路径，不产生真实执行记录、生产染色或实验指标，也不证明 Core 分桶结果。

## 本地数据与兼容

- 使用单独、版本化的浏览器草稿键保存活动 ID、实验节点 ID、实验定义 ID、插入点、三组连接及仅构造 ID 的节点模拟染色。既有 `gmp-audience-demo-v1` 和管理 API 数据格式不升级、不迁移。
- 对本地草稿的读取与写入记录结构化结果日志，只含操作名和结果，不输出构造 ID、浏览器存储原文或其他敏感信息。
- 读取草稿时严格校验版本、结构与引用；损坏时保留原始值、提示不可用，不静默丢弃或覆盖。保存失败只保留当前会话状态并明确提示；跨标签页并发不作为真实染色保证。
- 浏览器本地草稿可随页面刷新恢复，但不能在另一设备或 API 进程中出现。后续接管理 API 与 Core 时，应重新设计版本化契约和真实染色存储；不能把此浏览器键直接当生产迁移源。

## 验收与回退

- 从普通活动受众出发，在入口和投放项回执后分别插入实验节点；选择实验库定义、配置三组去向，画布显示节点与分支，本地演练只给到达节点的人分组。刷新后草稿仍在；受众侧的分组和流程节点分组互不影响。
- 实验引用停用、目标投放项被删除、分组连接缺失、循环、草稿损坏及浏览器写入失败均有明确阻断或修复提示；没有路径会静默落到错误投放项。
- 桌面与 390px 窄屏可操作，键盘可到达新建、编辑和删除；前端回归、离线导出、文档门禁和实际浏览器走查通过。
- 本轮不改管理 API、Core 或真实活动执行。回退前端节点编辑与独立浏览器草稿读取即可恢复现有 API 流程显示；原活动和受众数据不需回填。此设计获批后另建 issue 与实施分支，不并入 issue #80 的既有两项未通过评估问题。

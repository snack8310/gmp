# gmp-core README 分层状态修订

## 意图

让 `gmp-core/README.md` 准确反映当前主线：`audience`、`campaign`、`scenarios` 已有实现和测试，但实现范围与业务场景覆盖仍不完整。README 过期会误导 Core 能力判断。

## 目标

- 修正依赖分层表中已经过时的“未建立”状态。
- 修正“本轮未覆盖”中把已有层整体列为未建立的表述。
- 明确保留内存模型、未覆盖场景、指标范围和管理 API / Core 尚未接入的活动流程实验节点等边界。

## 非目标

- 不改 Go 代码、接口、领域规格、依赖方向检查或业务回归。
- 不把本地演练描述成 Core 能力，不宣称生产就绪或所有规格已实现。
- 不把 README 扩写成完整功能目录。

## 方案

- **选定：最小状态修正。** 仅改分层状态和未覆盖项；依据当前包、测试与近期变更记录逐项措辞。优点是直接消除错误事实，范围和审查成本都小。
- **未选：扩写完整能力总览。** 需要重新核对各领域规格、所有实现与未覆盖场景，会扩大为全量 Core 文档审计，超出本 Issue。

用户已选择最小修正方案。实现只触及 `gmp-core/README.md`；任务卡、设计稿和变更证据属于仓库协作流程产物。

## 验收

- 各层状态与当前代码相符，但不暗示领域能力完整。
- 跨层场景回归的覆盖范围表述准确。
- 真实存储 / 外部链路、时间 / 并发验证、指标范围，以及活动流程实验节点的 API/Core 接入仍保持为未覆盖项。
- 不改变代码或外部行为。

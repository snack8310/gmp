# 纯业务 Core 与外层 MySQL 持久化实施计划

> **执行方式：**主 Agent 在现有 Issue #88 分支内按任务顺序实施；每个边界先用失败用例明确行为，再改生产代码。最终提交 Draft PR，不合并。
>
> **目标：**让 gmp-core 只保留显式值输入 / 输出的业务规则；外层应用负责来源读取、实验 / 活动数据持久化与运行编排。现有 /api/v1 契约保持兼容。
>
> **已确认输入：**Core 不持有存储（包括内存实现）；人群成员经来源接口取得；首个来源方向为只读 MySQL 用户池；实验、活动与受众配置由 Core 外的业务层持久化。
>
> **未确认边界：**用户池 schema、字段与分页契约尚未提供；不连接真实用户池、不写查询假设。执行、回执、outbox 是否一并持久化仍待用户明确；在答复前不将其计入本阶段持久化目标。浏览器演示草稿与构造种子不迁移。

## 架构约束与评估重点

- gmp-core 不定义 Store / Feed / Log 等 I/O 端口，不保存可变注册表，不包含 Memory 实现；纯规则只消费业务值并返回结果。
- 应用层定义自身需要的 repository / source 接口，MySQL 实现放 management 外层；生产启动必须显式提供平台 MySQL 配置，失败时不回退到内存实现。
- 人群成员只在一次求值中临时读取，不落平台表、不写日志；配置缺项必须在启动 / 请求边界失败。
- 实验染色使用 (AssignmentID, AssignmentKey) 唯一性；并发竞争必须读回唯一约束的获胜值。
- 流程边的 UID、placements、上游回执归属与派生执行 key 保持现有领域语义；若执行态移出本期，须明确标为未覆盖，不得声称已验证。
- 现有 /api/v1 请求 / 响应保持兼容；API 管理投影与 Core 值对象的转换必须显式，不能维护另一套业务判定。
- 评估器输入仅含任务卡、实现 / diff、命令证据与必要规格；结论不由主 Agent 改写。

## 实施任务

### Task 1：构造 Core 纯值输入 / 输出边界

**范围：**gmp-core/experimentation/、gmp-core/audience/、gmp-core/campaign/ 与 gmp-core/scenarios/。

- [ ] 先为实验分配、受众判定、活动决策 / 状态转换写不依赖 Store 的输入 / 输出回归。
- [ ] 将染色读取 / 写入、受众 Feed、活动 / 实验注册与执行日志编排从 Core 迁出；Core 留确定性函数与可序列化 / 可构造领域值。
- [ ] 将现有演练对内存 adapter 的依赖移至外层应用 / 测试支持；gmp-core/scenarios/ 留纯业务场景输入 / 输出断言，执行态集成用例归外层 module。
- [ ] 扩展架构门禁，确保 Core 包内没有存储 / I/O 端口与内存 adapter，并让新增包漏列或规则空跑时测试失败。

### Task 2：外层应用、领域转换与 MySQL 连接

**范围：**management/、管理 API 启动器及 CI。

- [ ] 用可验证的接口将 API DTO 转换为 Core 领域对象；所有写入先经过 Core 构造 / 校验。
- [ ] 在外层应用定义受众、实验、活动的 repository 与来源接口；平台 MySQL 只保存平台拥有的配置 / 染色状态，不保存用户池成员快照。
- [ ] 添加必填 MySQL 连接配置、连接池关闭生命周期、版本化 migration 与启动 schema 检查；缺配置 / 迁移失败立即失败。
- [ ] 为受众 / 实验 / 活动领域配置与染色建立对应关系表和必要唯一约束；不迁移演示数据。
- [ ] 保持现有 /api/v1 JSON 契约；外部调用日志只记录动作、结果与耗时，不包含 DSN、用户标识或业务载荷。

### Task 3：来源适配器边界

**范围：**外层受众读取适配器及配置校验。

- [ ] 建立只读来源 adapter；表 / 视图、UID 列、允许读取字段、筛选与分页参数均为显式必填配置并校验标识符。
- [ ] 适配器只投影本次求值所需的构造输入，关闭写入路径，不缓存 / 快照来源成员。
- [ ] 真实查询联调须等用户提供表结构、字段、查询 / 分页契约与允许环境；本计划不连接任何实际用户池。

### Task 4：真实 MySQL 契约和送审

**范围：**management 集成测试、CI、任务卡与 PR。

- [ ] 使用可复现的 MySQL 测试实例验证迁移、CRUD、事务失败原子性、并发染色、已有 API 行为。
- [ ] 对实际用户池适配器只验证必填配置 / SQL 边界；缺真实 schema 时记录为未覆盖。
- [ ] 执行两个 Go module 的格式、build、vet、unit / integration 验证及文档一致性门禁；所有成功凭据来自执行命令。
- [ ] 记录变更证据，核送审 SHA 与 PR 正文一致。
- [ ] 提交评估器审查包；仅保留评估器原始裁决，Draft PR 未获 PASS 时不请求人工最终审核。

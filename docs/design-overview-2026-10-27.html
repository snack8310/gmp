1. Action 一等公民 事实 63–66

动作（Action）与来源、实验人群包同级，是研发接入的能力清单；不是投放项上的附属字段。

边界表（已确认）

边界含义
投放项 ≠ 动作类型 投放项（Treatment）是活动下的可执行单元；动作类型（展示 / 短信 / 权益）是动作目录里的分类，不是投放项本身。（事实 64）
投放项引用动作 投放项挂一个动作并填该动作要的参数；一个投放项只能是一类动作（事实 52、64）。
动作定义成功 / 失败 / 异步回执 何种结果算成功、失败、是否有异步回执，由该动作契约写清；平台按此做回执关联（事实 65；关联事实 41、48）。
展示位 ↔ 展示类动作 展示位对应展示类动作；通常一次判定产出一个展示结果（一个素材 id）。同展示位多活动抢位仍按事实 5–7、23。（事实 66）

与「来源」对称

进来出去
来源 —— 人从哪来动作 —— 东西怎么出去
研发预先接好，运营从列表里挑同样：研发接好、运营挑
拉 / 推整批 / 推逐条展示 / 发短信 / 发权益
事实 40（不推翻）： 三类动作都跟外部系统打交道，但方向不同——短信 / 发券是我们调对方；资源位是对方调我们、我们返回 id。资源位没有「发放成功」；返回 id ≠ 被看见（曝光回传不强制，见事实 50、51）。
已知代价 / 未定： 素材不是一等公民（事实 39）——跨投放项按素材归因做不了。内容不做统一模型，是动作参数（事实 37）。「展示素材归谁持有」文档仍写未定。各动作字段级成功/失败枚举本轮只定「由动作定义」，细则待后续。

出处：docs/domain/campaign-user-stories.md（动作一节；事实 36、40、63–66）；docs/history/changes/2026-10-27-action-first-class.md；归属见 system-boundaries.md。

2. 业务模型与分层

依赖单向、无环：运营平台引用受众与实验；受众引用实验；实验服务零依赖另外两层。

运营平台（campaign）
活动、投放项、决策表、优先级、放量旋钮、动作 Action。
回答：「要对这些人做什么」
引用 ↓
受众服务（audience）
来源、人群配置、人群组、实验人群包（发布单元）。枚举 / 判定。
回答：「这个人是谁 / 这批人是谁」
引用 ↓（「第 N 份」只是普通人群条件）
实验服务（experimentation）
一次分流：份数、比例、盐、对齐；稳定分配；实验指标。
回答：「这个 id 落在第几份」· 不得依赖另外两层
产品偏好（已确认，不改接缝）： 大部分分组实验落在人群侧（实验人群包跨活动复用）；活动内再建分流是例外。分桶本体仍归实验服务；受众服务自己不分桶。

投放项与人群怎么挂

投放项类型挂什么问受众要什么
我们找人 · 批量一个人群组枚举：这批人是谁
我们找人 · 事件触发器 + 人群配置判定判定：他算不算
人找我们 · 资源位准入条件判定：他算不算（须快）

一个投放项 = 对一个人做一件事（一步）。多步靠事件串，投放项互不相识。——「事件串」只是白话，不是平台对象。

出处：docs/domain/system-boundaries.md 拆法与归属表；campaign-user-stories.md 投放项与受众关系。

多动作三种表达 事实 67

「权益 + WhatsApp + 短信」等诉求用现有模型表达：仍保持一个投放项一个动作；不引入编排器 / 「串」对象。成功 / 失败语义由动作契约定义。

表达怎么配短例对应事实
并行 同一人群组挂多个投放项 新客同时发权益、WhatsApp、短信 事实 52
串行 后一步人群建在前一步执行回流来源上 发权益 →「已发权益」→ WhatsApp → 短信 事实 17、18
按回执分支 成功 / 失败（及契约其他结果）回流后各建人群组 + 投放项 RCS 成功→邮件；失败→短信 事实 18、65
不推翻：事实 11 / 52 / 64——一个投放项仍只挂一个动作；多动作 = 多个投放项。条件分流仍 = 人群组 + 投放项。

出处：campaign-user-stories.md「多动作的三种表达」；事实 67；docs/history/changes/2026-10-28-multi-action-expression.md。

完整流程示意 · 新客召回

把「活动 → 人群 → 并行投放 → 回执回流 → 按结果分支」串成一条可读故事。图中每一个投放项仍只挂一个动作；先后与分支靠回流来源接上，没有编排器。

活动 / 放量 人群配置 / 人群组 投放项 动作 / 回执 约束标注
  1. 建活动并调活动级放量旋钮（灰度先小后大）。
  2. 人群配置选出人 → 挂出人群组；需要 AB 时用实验人群包出多臂。
  3. 并行：同一人群组挂 T1 发权益、T2 发 RCS（各一个动作）。
  4. 执行产生回执，回流成来源，再配下游人群。
  5. 按回执分支：成功人群 → T3 发邮件；失败人群 → T4 发短信。
读图要点： 图里没有「流程编排」节点——先后与分支全是「回流来源 → 新人群组 → 新投放项」。并行与分支可同活动共存。

出处：事实 11 / 17 / 18 / 52 / 64 / 65 / 67；对应上一节「多动作三种表达」与 business-scenarios.md 新客 / 跨境场景。

3. 人群配置 · 人群组 · 实验人群包

关闭「人群定义 / 来源」命名歧义后的主名（事实 26；AQ1–AQ3）。

主名建议英文一句话
人群配置 AudienceConfig（建议；代码暂仍 audience.Definition） 来源 + 筛选。筛人是配置的一部分。有枚举与判定两种求值用法。勿再以「人群定义」当主名。
人群组 AudienceGroup（建议） 受众对外挂接。无实验 → 组数 = 1；有实验 → 实验人群包下多臂多组。活动 / 投放项挂的是人群组，不是来源本身。
实验人群包 ExperimentAudienceBundle（建议；拼写待命名确认 D9） 一等公民发布单元：同一来源上的一次分流 + 各臂人群组，打包发布后可被多活动引用。不是新的分桶机制（每臂内部仍是带「第 N 份」的人群配置）。
来源 AudienceSource 能吐 uid 的供给方；不含筛选。研发预先接好，运营只能从列表挑。

AQ 结论（已关闭）

  • AQ1：实验人群包另立一等公民，分流与各臂打包发布（事实 23）。
  • AQ2：分流修订 / 停用 → 强制停用相关臂及包可用状态（事实 24；不变量 20）。
  • AQ3：同一臂被多活动引用时，按臂跨活动聚合 与 按活动切开两种视图都要（事实 25、61；不变量 21）。

出处：audience-user-stories.md 名词表 / 事实 23–26；2026-10-27-audience-naming-rewrite.md；2026-10-27-experiment-audience-bundle-aq.md。

4. Source（来源）边界

  • 来源与「运营配的那次筛选」拆成两个东西（事实 8）——生命周期不同；筛选在人群配置里只有一处（Q8）。
  • 来源分两类：外部系统，与平台自身执行结果回流（事实 11）——条件分流的前提。
  • 三种供给方式共同点是「能吐 uid」，区别在谁主动（拉 / 推整批 / 推逐条）。
  • 语义上多个活动共用同一来源互不影响；唯一例外是对方配额 / 限流（Q10）。
  • 执行结果回流不成环：运营平台只往外发事件，受众服务当普通来源消费，从不反向调用运营平台（边界文档）。
文档未定：「一份人群配置能否跨多个来源」见受众侧故事 6（仍待确认）。

5. 分流组件运行时规则 事实 27–28 · 62

分流组件 = 产品说法；本体是实验服务的一次分流定义。经实验人群包发布后，各臂对外为人群组。

状态允许禁止
运行中
无论是否已被活动引用		 调整比例、白名单等运行参数。
运行参数调整 ≠ AQ2「分流修订」，不因此强制停用臂。		 改「加载组件逻辑」（换算法 / 切法结构 / 组件实现等使历史分配与染色语义不可比的变更）。
非运行中 — 不可被其他活动引用（不得新挂为有效人群；已挂须随停用路径失效）。进入非运行 / 分流被修订停用时仍适用 AQ2。
文档未定：「加载组件逻辑」英文名未定；切法份数增减是否一律算加载逻辑、白名单数据结构未细拆；运行中调比例后未染色键是否立即按新比例重算——机制仍见染色表，本轮不新开算法事实。gmp-core 代码仍可能按旧「定义不可就地修改」实现，对齐另开任务。

出处：受众侧事实 27–28、能力 A11；活动侧事实 62；2026-10-27-split-component-runtime-rules.md；不变量 22–23。

6. 使用 / 运营流程

下列步骤综合领域文档能力顺序，以及 frontend/demos/operations-flow 演示沙盘的操作路径。Demo 是展示沙盘，不是生产平台；领域里尚待确认的功能不因 Demo 变成业务决策。

领域口径下的配置顺序

1
研发接入来源与动作 运营只能从已接好的列表里挑（来源 A1；动作事实 36 / 63）。
2
配置人群 选来源 + 加筛选 → 人群配置；需要 AB 时引用分流「第 N 份」条件，或发布实验人群包（各臂 = 人群组）。
3
建活动与投放项 活动下挂投放项：每个投放项引用一个动作 + 一个人群组；需要时配决策表 / 优先级 / 放量旋钮。
4
多步靠事件串 例如「发券 → 3 天未用再短信」= 两个投放项；第二步触发条件来自平台执行结果回流成来源。
5
止血 vs 修复 止血：停活动 / 停投放项；修复：改人群配置（会波及其他引用方）。分流组件非运行中不可被新活动挂上。

Demo 泳道（operations-flow，仅演示）

人群管理
预置 / 新建人群；选进入方式（批量排期或事件触发）；配来源 + 圈选条件；可选绑定 A/B 实验；保存的是入口配置与规则引用，不是名单。
沙盘引用
「引用到沙盘」或选已保存人群；画布只读显示入口配置；切换 / 改人群会重置并暂停，并清空流程实验节点以免隐式套用。
流程节点
可选在路径上加一个流程实验节点（进入后分流，非入口配置）；对照路径不触达；模拟播放看统计。同实验 ID 同用户分组稳定。
明确不做
不接生产服务、不上传名单、不真发消息、不建设通用图引擎或生产实验配置平台。
五个已确认业务场景（压模型用，见 business-scenarios.md）：① 新客首单转化（事件串）② 双十一分组实验 ③ APP banner 抢位 + 决策表 ④ 灰度放量 ⑤ 跨境两级触达（回流 + 幂等）。

出处：frontend/demos/operations-flow/README.md；business-scenarios.md；受众 / 活动能力表。

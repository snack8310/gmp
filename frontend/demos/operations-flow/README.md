# GMP 管理后台演示

独立前端管理演示，最左侧提供「活动、受众、实验」三个一级菜单。活动是运营内容的核心，活动详情展示投放项清单，并嵌入历史版本的 3D 流程画布；画布按当前活动呈现受众入口、投放项和活动流程边。活动及其人群引用通过管理 API 写入平台 MySQL；受众规则、实验定义、实验人群包和模拟样本仍是当前浏览器中的构造演示数据，不接真实人群池、生产分桶或渠道。

## 运行与导出

活动管理需要同时启动本机管理 API 和同源演示入口。在不同终端分别运行：

```sh
cd management
# 从安全配置来源注入以下必填变量，不要把凭据写入仓库或 shell 历史。
export MYSQL_DSN
export MYSQL_MAX_OPEN_CONNS
export MYSQL_MAX_IDLE_CONNS
export MYSQL_CONN_MAX_LIFETIME_SEC
go run ./cmd/campaign-api -addr 127.0.0.1:8082
```

另一个终端启动同源演示入口：

```sh
node frontend/demos/operations-flow/serve.mjs 8081 8082
```

打开 `http://127.0.0.1:8081`。演示入口在同一源代理 `/api/v1/*` 到管理 API。只用普通静态服务启动页面时没有 API 代理，活动列表和活动内容不可用。默认 API 基址使用当前页面源；需要覆盖时，在载入 `app.mjs` 前设置 `window.CAMPAIGN_API_BASE`。

容器试运行在仓库根目录执行 `docker compose build` 和 `docker compose up -d --wait`，访问同一地址，停止时执行 `docker compose down`。Compose 为页面和管理 API 分别启动容器，页面通过内部服务名代理 API；宿主机只映射页面的 `127.0.0.1:8081`。可在启动命令前设置 `GMP_DEMO_PORT` 改宿主机端口。需要外部访问时，应由带 TLS 和访问控制的反向代理接入页面端口；演示本身没有鉴权，不应直接公开。

Compose 启动前必须从安全配置来源注入 API 所需的四项 `MYSQL_*` 变量，DSN 要从容器网络访问到平台自有 MySQL。Compose 不含数据库凭据或 MySQL 服务。容器启动将 `GMP_DEMO_LISTEN_HOST` 设为 `0.0.0.0`、`GMP_DEMO_API_HOST` 设为 `api`。直接运行 `serve.mjs` 时这两项默认都是 `127.0.0.1`，原本机命令无需修改。显式设置为空会使入口启动失败。

单文件导出：

```sh
node frontend/demos/operations-flow/export.mjs /tmp/gmp-activity-demo.html
```

导出文件内联样式和管理界面模块，可离线打开。`file://` 没有 HTTP 同源 API，因此不会显示伪造的活动列表；页面会明确提示 API 不可用。

## 功能

### 活动

- 活动列表由管理 API 提供。选择活动后直接进入活动详情，可新建、编辑或删除活动。
- 活动详情显示其投放项列表。可新增、编辑和删除投放项；每个投放项选择一个动作和可选展示位。活动本身只选择一个普通人群组或一个已发布实验人群包。
- 活动详情在投放项清单下显示历史 3D 流程画布，保留原有 SVG 投影、节点绘制、视角切换、拖动旋转和路径播放。流程入口把所选人群组映射到一个或多个起始投放项；选择实验包时，按实验臂映射到不同起始路径。后续步骤由回执边连接。
- 新建或改名的普通共享人群会把稳定引用 ID 与显示名同步到本机管理 API 目录，之后可在活动编辑页选择。圈选规则和模拟样本仍只保存在当前浏览器；实验包臂从共享目录读取，不复制实验定义。
- 可在画布配置投放项之间的回执边；服务端检查边端点、重复路由、动作声明的回执结果和循环。活动配置与人群引用写入平台自有 MySQL。
- 本地演练仅按动作目录声明的回执结果依次轮转，帮助查看活动边路径；它不代表概率、真实分桶、真实触达或业务效果。
- 活动受众区只负责选择普通人群组或已发布实验人群包；其下独立的「活动实验」区可在入口、回执出口或已有实验分组路径插入实验节点，引用运行中的实验库定义，并设置 A/B/对照三组去向。节点和连接仅保存在当前浏览器的 `gmp-flow-experiment-draft-v1` 草稿键，不会写入管理 API，也不参与真实执行。
- 画布合并展示 API 流程和浏览器草稿；只有到达实验节点的构造用户才在该节点分组。受众侧与各节点分别使用独立分配身份。显式播放时才记录节点的首次模拟染色，节点检查器显示分组人数与路径到达次数。停用定义或失效连接会阻止本地演练。
- 活动受众选择器和流程入口配置只接受管理 API 当前开放的引用。普通共享人群目录项在应用载入、保存或改名时同步；引用会持久化到平台自有 MySQL。

### 受众

- 受众库支持搜索、新建、编辑、删除和匹配预览。配置可复用的人群来源、进入方式、圈选条件和可选实验。
- 删除人群前会读取活动和服务端引用占用；读取失败或仍被引用时拒绝删除。
- 发布实验人群包是单独动作：选择已保存且引用运行中实验的人群，生成 A、B、对照臂。只有已发布的人群包臂会出现在相应引用目录。
- 受众定义、实验定义、实验人群包及构造用户的模拟染色保存在浏览器 `gmp-audience-demo-v1` 命名空间，不跨设备同步。旧格式在首次写入新版前备份到 `gmp-audience-demo-v1-backup-v4`；存储异常时回退到当前会话内存，不会静默清理原缓存。

### 实验

- 实验库采用列表、新建和独立详情页，支持搜索、创建、改名、运行、停用、调整 A/B/对照比例和删除。比例须为整数百分比且合计 100%；运行中调整不会令已发布包失效。被受众、人群包或本地活动流程节点引用的实验不可删除。
- 创建时必须选择是否记录首次模拟分配；策略创建后不可修改。详情的构造样本预览只读，点击「模拟首次分配」才会记录本地染色；已记录构造 ID 在比例调整后仍保持原臂。受众预览读取同一份配置与记录，但不会写入染色。这里不写生产染色记录，也不提供放量配置、白名单或指标。
- 本地分桶哈希仅用于演示，不能据此推断 Core 对某个用户的实际分桶结果。浏览器缓存不提供跨标签页原子写入保证。

## 边界

- 活动、投放项、流程边及普通人群引用由管理 API 写入平台自有 MySQL；新 schema 不自动导入构造种子，API 启动失败时不会退回进程内存状态。当前实现会在事务内读写完整配置，面向演示与边界验证，不是生产规模方案。
- 受众和实验定义及模拟样本仅保存在当前浏览器；本机 API 仅持有活动引用所需的人群 ID 与显示名。不上传名单、不接真实渠道、不调用生产分桶算法，也不执行真实触达。
- 活动流程边由管理 API 持久化到平台 MySQL。受众引用、回执条件和活动内边语义不由浏览器临时推断。
- 流程实验节点只属于浏览器草稿，不具备管理 API/Core 的保存、跨设备同步、生产染色或真实指标口径。损坏的草稿原文会保留并阻止继续保存；浏览器写入失败时当前会话的修改不会在刷新后恢复。后续接入 API/Core 需单独设计版本化契约。
- Docker 只封装上述演示的页面与 API；活动与引用写入注入 DSN 指向的平台 MySQL。受众规则、实验定义与流程实验草稿仍保留在原浏览器，换设备不会同步。
- 旧版离线页面不能读取新版浏览器缓存。需要回退时，先把 `gmp-audience-demo-v1-backup-v4` 的原文恢复到 `gmp-audience-demo-v1`，再打开旧版页面；新版期间所做的修改不会出现在备份中。

## 验证

```sh
node --test frontend/demos/operations-flow/*.test.mjs
python3 test/docs/consistency_check.py
```

修改模块后可用 `node --check <模块路径>` 检查语法。桌面与窄屏浏览器主路径可用仓库内 `browser-check.mjs` 辅助走查；真实渠道、生产性能和跨浏览器矩阵不在此演示的覆盖范围内。
